# 统一身份认证（CAS 2.0）单点登录

## 1. 功能范围

登录页在原账号密码登录之外新增「统一身份认证登录」入口，两个入口并存：

1. 浏览器访问 `/api/v1/user/sso/cas/login`，后端签发一次性 `cas_state` cookie 并跳转
   `{CAS_BASE_URL}/login?service={回调地址}`；
2. 认证平台带一次性 `ticket` 跳回 `/api/v1/user/sso/cas/callback`，后端回访
   `{CAS_BASE_URL}/serviceValidate` 换取工号；
3. 准入通过后，后端查找或自动创建本地账号、补建工作区成员关系并签发正常的 LangBot JWT；
4. 回调只把 JWT 放进有效期 120 秒的 HttpOnly cookie，然后跳转 `/login?sso=1`；
   登录页调用 `POST /api/v1/user/sso/session` 兑换 `{token, user}`，再走原有登录收尾流程。

JWT 不会出现在 URL、浏览器历史或前端日志里。

### 不做单点登出（SLO）

本实现**没有**单点登出。用户在认证平台退出后，认证平台仍可能保留浏览器侧会话，
再次点击「统一身份认证登录」会被静默重新放行，这是 CAS 单点登录的预期行为。

LangBot 本地的「退出登录」仍使用原有逻辑：清除本地 JWT 并回到登录页。它只结束
LangBot 会话，不会通知认证平台，也不会结束其它接入认证平台的应用。

## 2. 准入规则

- 身份类别取自 CAS 属性 `usertype`，默认只允许 `teacher`；
  `allowed_user_types` 支持逗号分隔多个值，`*` 表示不限制。
- **缺失 `usertype` 一律拒绝**（fail closed），不会因为属性缺失而放行。
- 被拒绝时回调返回 `/login?error=sso_usertype_forbidden`，不建号、不下发会话。
- 账号被停用、或工作区成员关系被移除/停用，均拒绝登录；不会因为 SSO 登录而自动恢复。

## 3. 自动建号与权限

- `auto_provision: true`（默认）时，首次登录会创建**无密码**本地账号，账号名即 CAS 工号。
  每次建号与成员关系写入在同一个事务中完成，任一步失败都会整体回滚。
- `auto_provision: false` 时只允许已存在的本地账号登录。
- 自动创建的账号会加入当前实例的唯一工作区，角色为 `operator`：可以查看工作区并使用
  聊天运行时，但不能管理模型、知识库和成员。管理员可在「成员管理」中调整角色或移除成员。
- 实例必须先完成初始化（存在本地账号与工作区）。SSO 不会成为抢占 owner 的初始化入口。

## 4. 配置

配置位于 `data/config.yaml` 的 `sso.cas`，也可以用双下划线环境变量覆盖
（旧配置文件缺少该段时，环境变量会自动创建）：

| 配置项 | 环境变量 | 说明 |
|---|---|---|
| `enabled` | `SSO__CAS__ENABLED` | 总开关，默认 `false` |
| `base_url` | `SSO__CAS__BASE_URL` | CAS 根地址，**必须带 context path**，如 `https://sso.lnc.edu.cn/lyuapServer` |
| `service_base_url` | `SSO__CAS__SERVICE_BASE_URL` | 本系统浏览器访问源（只有协议+主机+端口，不带路径和 query）；为空时依次回落到 `api.webui_url`、`api.webhook_prefix` |
| `service_path` | `SSO__CAS__SERVICE_PATH` | 回调路径，默认 `/api/v1/user/sso/cas/callback`，一般不需要改 |
| `state_secret` | `SSO__CAS__STATE_SECRET` | `cas_state` 的 HMAC 密钥，至少 16 字符；为空时回落到 `system.jwt.secret` |
| `state_ttl_seconds` | `SSO__CAS__STATE_TTL_SECONDS` | state 有效期，默认 300 秒 |
| `cookie_secure` | `SSO__CAS__COOKIE_SECURE` | `auto`（按 `service_base_url` 是否为 https）/ `true` / `false` |
| `allowed_user_types` | `SSO__CAS__ALLOWED_USER_TYPES` | 允许的 `usertype`，默认 `teacher` |
| `auto_provision` | `SSO__CAS__AUTO_PROVISION` | 是否自动建号，默认 `true` |
| `timeout_seconds` | `SSO__CAS__TIMEOUT_SECONDS` | 回访认证平台超时，默认 10 秒 |
| `rate_limit_per_minute` | `SSO__CAS__RATE_LIMIT_PER_MINUTE` | 每客户端每分钟登录/回调次数，默认 20 |
| `ca_cert_path` | `SSO__CAS__CA_CERT_PATH` | 自定义 CA 证书路径 |
| `insecure_skip_verify` | `SSO__CAS__INSECURE_SKIP_VERIFY` | 仅测试使用，生产不要开启 |
| `button_label` | `SSO__CAS__BUTTON_LABEL` | 自定义按钮文字，空值使用界面语言文案 |

示例（`deploy/prod/.env`）：

```dotenv
SSO_CAS_ENABLED=true
SSO_CAS_BASE_URL=https://sso.lnc.edu.cn/lyuapServer
SSO_CAS_SERVICE_BASE_URL=http://<生产访问地址>:5300
SSO_CAS_STATE_SECRET=<openssl rand -hex 32 的输出>
SSO_CAS_ALLOWED_USER_TYPES=teacher
```

> `SSO_CAS_SERVICE_BASE_URL` 填浏览器实际访问生产系统的源（协议 + 主机 + 端口），
> 回调地址 `{SSO_CAS_SERVICE_BASE_URL}/api/v1/user/sso/cas/callback` 必须与学校登记值
> 逐字符一致。本地 demo 与生产各填各的，互不影响。

## 5. 部署前置条件

1. **登记回调白名单**：把 `{service_base_url}{service_path}`（逐字符一致，且不带 query）
   提交给学校认证平台登记。本地 demo 与生产必须分别登记各自的回调地址，例如生产为
   `http://<生产访问地址>:5300/api/v1/user/sso/cas/callback`。
2. **出网要求**：LangBot 所在主机必须能访问 `base_url` 指向的认证平台。生产服务器即使
   不能访问公网，也必须能访问学校的 CAS 内网地址；否则会返回 `sso_unreachable`。
   可在服务器上直接验证：
   `curl -s "https://sso.lnc.edu.cn/lyuapServer/serviceValidate?ticket=invalid&service=x"`
   ，返回 CAS XML（`authenticationFailure`）即表示连通。
3. **访问地址一致**：浏览器地址栏的 host 必须与登记的 `service_base_url` 完全一致。
   `localhost` 与 `127.0.0.1` 是两个不同的 cookie host，混用会导致 `sso_state` 失败。
   使用反向代理时请保留原始 `Host`（或传递 `X-Forwarded-Host`）。
4. **TLS**：若 CAS 使用学校自签 CA，配置 `ca_cert_path`；不要在生产开启
   `insecure_skip_verify`。
5. **多工作区 / Cloud 模式**：SSO 自动建号只在单工作区 OSS 部署中启用。多工作区模式由
   控制面管理账号目录，回调会返回 `sso_disabled`。

### 生产启用检查表

1. 确认生产地址已确定，且回调已按该地址登记（`http://<生产地址>:5300/api/v1/user/sso/cas/callback`）。
2. 构建并传送镜像：`./deploy/prod/build-image.sh` → `./deploy/prod/ship-image.sh <tag>`。
3. 在 `/opt/langbot/.env` 填写 `SSO_CAS_*`（见第 4 节），`LANGBOT_IMAGE` 指向新标签。
4. `sudo docker compose --env-file .env up -d` 重建容器（`restart` 不会加载新环境变量）。
5. 验证：`curl -s http://<生产地址>:5300/api/v1/user/account-info` 返回
   `"cas_login_enabled": true`；用登记的地址在浏览器打开登录页，应出现
   「统一身份认证登录」按钮。
6. 用教师账号走一遍完整流程；若失败，按第 6 节错误码排查。

## 6. 错误码对照

| 错误码 | 含义与处理 |
|---|---|
| `sso_state` | state 缺失、被篡改或过期。多为 host 不一致或停留过久，重新点击登录 |
| `sso_host_mismatch` | 浏览器 host 与登记的 `service_base_url` 不一致 |
| `sso_username` | CAS 返回的工号不符合本地账号规则（3–40 位字母数字 `._-`，不含 `@`） |
| `sso_usertype_forbidden` | `usertype` 缺失或不在允许列表（学生账号会落到这里） |
| `sso_ticket_invalid` | ticket 无效、已使用或认证平台返回认证失败 |
| `sso_unreachable` / `sso_timeout` / `sso_tls` | 网络、超时或证书问题，检查出网与 CA 配置 |
| `sso_invalid_response` | 认证平台返回非预期内容，常见于 `base_url` 漏写 context path 或返回 3xx |
| `sso_disabled` | 未启用、实例未初始化、自动建号关闭且账号不存在，或运行在多工作区模式 |
| `sso_account_disabled` | 本地账号被停用，或工作区成员关系被移除/停用 |
| `sso_rate_limited` | 同一客户端一分钟内请求过多，等待后重试 |
| `sso_unavailable` | 认证平台返回非 200，或本地服务暂时不可用 |

## 7. 安全说明

- CAS 返回的 `email`、`edupersoncard`（身份证号）、`sex`、`realname` 不会被记录、落库或
  传给前端；`realname` 是 Base64 编码的中文姓名，本实现不将其作为显示名使用。
- 后端日志只记录稳定的错误码，不记录工号、ticket 或 CAS 原始响应。
- `cas_state` cookie 为 `HttpOnly` + `SameSite=Lax`（回调是跨站顶层跳转，`Strict` 会导致
  浏览器不发送该 cookie）；会话兑换 cookie 为 `HttpOnly` 且仅 120 秒有效。
- `service` 参数只由 `service_base_url` + `service_path` 构造，从不读取请求头推导，也不带 query。
- CAS 失败同样是 HTTP 200 + XML，因此以 `<cas:authenticationFailure>` 判断，而不是看状态码。
