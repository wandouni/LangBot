# 管理员账号说明

本文说明 LangBot OSS / 自托管部署（`deployment_mode: oss`）中管理员账号的来源、创建方式、角色权限与密码找回方式。

> LangBot Cloud 走 LangBot 账号登录，密码登录被禁用，不适用本文的本地账号流程。

## 1. 结论：没有默认管理员

LangBot **不内置任何默认管理员账号或默认密码**：

- `src/langbot/templates/config.yaml`、`deploy/prod/.env.example` 中都没有管理员账号、密码或初始化种子配置。
- 数据库为空时，服务启动后不会自动创建用户；第一个通过 WebUI 初始化的账号才成为管理员。
- 初始化只能执行一次，已有任意账号后接口会返回 `System already initialized`。

## 2. 首次创建管理员

### 2.1 操作步骤

1. 部署完成后访问 WebUI，例如 `http://<host>:5300`。
2. 未初始化时，登录页会自动跳转到 `/register`。
3. 填写**邮箱 + 密码**提交。该账号即成为：

   - Workspace 的 **owner**（最高权限角色）；
   - 后续所有配置（模型、平台、插件、成员）都以该账号完成。

邮箱必须符合邮箱格式（包含 `@`），后端会统一转为小写作为登录身份。

### 2.2 确认初始化状态

```bash
curl -s http://127.0.0.1:5300/api/v1/user/init
# 未初始化：{"code":0,"msg":"ok","data":{"initialized":false}}
# 已初始化：{"code":0,"msg":"ok","data":{"initialized":true}}
```

```bash
# 查看登录能力（密码登录、Space 登录、CAS 登录是否开启）
curl -s http://127.0.0.1:5300/api/v1/user/account-info
```

### 2.3 实现位置

| 行为 | 位置 |
| --- | --- |
| `GET/POST /api/v1/user/init` | `src/langbot/pkg/api/http/controller/groups/user.py:117` |
| 首个账号原子创建（仅当账号表为空） | `src/langbot/pkg/api/http/service/user.py:353` `create_initial_account` |
| 创建 `Default Workspace` 并授予 owner | `src/langbot/pkg/workspace/service.py:405` `bootstrap_local_account` |
| 角色定义 | `src/langbot/pkg/entity/persistence/workspace.py:29` |

## 3. 角色与权限

LangBot 的“管理员”是 Workspace 内的角色，不是独立的超级用户体系。

角色从高到低：

| 角色 | 说明 |
| --- | --- |
| `owner` | 拥有全部权限；每个 Workspace 只能有一个 active owner |
| `admin` | 除 `workspace.delete`、`billing_link.manage` 外的全部权限 |
| `developer` | 只读 + 资源管理、运行时操作、模型供应商密钥管理 |
| `operator` | 只读 + 运行时操作（可就最低限度地使用聊天运行时） |
| `viewer` | 仅只读 |

权限映射见 `src/langbot/pkg/api/http/authz.py:42`。

> 单 owner 约束由迁移 `src/langbot/pkg/persistence/alembic/versions/0019_single_workspace_owner.py` 保证；升级前存在多个 owner 的历史数据会被收敛为一个。

## 4. 后续如何增加管理员

### 4.1 邀请成员

1. 用 owner 登录 WebUI。
2. 左下角用户菜单 → **工作区** → **成员**。
3. 邀请成员并指定角色（可选 `admin`）。
4. 被邀请者通过邀请链接使用**同一邮箱**注册本地账号，注册后按邀请角色加入 Workspace。

实现：`src/langbot/pkg/api/http/controller/groups/workspaces.py` 的邀请与成员角色更新接口。

### 4.2 调整已有成员角色

owner 可在成员列表中把成员角色改为 `admin`。`admin` 拥有除删除 Workspace、管理账单链接之外的管理能力，适合日常运维管理员。

### 4.3 SSO / CAS 自动开通的账号

如果启用了 CAS 单点登录（`SSO_CAS_ENABLED=true`，默认关闭）：

- 首次 SSO 登录会自动创建本地账号并加入 Workspace，角色固定为 **operator**，不会自动成为管理员（`src/langbot/pkg/api/http/service/user.py:422` `_ensure_sso_membership`）。
- 被管理员禁用或移除的成员，SSO 登录不会自动恢复成员资格。
- 需要管理员权限时，仍由 owner 在成员管理中手动提升。

## 5. 忘记管理员密码如何找回

本地账号密码不需要重装或改数据库，使用内置的密码重置流程：

1. 打开 `/reset-password` 页面，或直接调用接口：

```bash
curl -s -X POST http://127.0.0.1:5300/api/v1/user/reset-password \
  -H 'Content-Type: application/json' \
  -d '{
    "user": "admin@example.com",
    "new_password": "<new-password>",
    "method": "recovery_key",
    "recovery_key": "<system.recovery_key>"
  }'
```

2. 实例恢复密钥位于数据目录的配置文件中：

   - 源码/本地运行：`data/config.yaml` → `system.recovery_key`
   - Docker 部署：`/opt/langbot/data/config.yaml`（容器内 `/app/data/config.yaml`）

3. 该密钥在首次启动时自动生成（8 位，字符集 `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`），生成逻辑见 `src/langbot/pkg/core/stages/genkeys.py`。**它是实例级主凭据，请离线备份并严格保密。**

4. 已启用 TOTP 二次验证的账号，也可以使用 `method: "totp"`（当前验证码）或 `method: "recovery_code"`（一次性恢复码）重置密码。

安全限制：

- 重置接口未登录可调用，但带 3 秒固定延迟和频率限制（约每 15 分钟 5 次），见 `src/langbot/pkg/api/http/controller/groups/user.py:243`。
- 若 `system.recovery_key` 为空或熵过低，启动日志会给出告警，应尽快重新生成强随机值。

## 6. 常见问题

**Q：能否通过环境变量或配置文件预置管理员？**

不能。初始化流程只接受第一个 WebUI 注册账号；SSO 自动开通的账号固定为 operator。

**Q：`/register` 提示系统已初始化怎么办？**

说明数据库中已有账号，直接去 `/login`。若忘记密码，按第 5 节重置，不要删除数据库。

**Q：能不能有多个 owner？**

不能。每个 Workspace 只允许一个 active owner；需要多人管理时，给其他人分配 `admin`。

**Q：LangBot 4.x 能否从 3.x 数据库升级并沿用旧管理员？**

不支持直接升级 3.x 数据库。4.x 需要新库并按本文重新初始化管理员。
