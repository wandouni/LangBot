# LangBot + SqlBot + 应用中心 生产环境部署指南

适用于本仓库（LangBot 4.11.2 定制分支）与 SQLBot（`dev` 分支定制版）在内网服务器上的单机 Docker Compose 部署。

覆盖五件事：

1. 首次部署：LangBot、SqlBot、应用中心、nginx 统一网关；
2. 登录 → 应用中心 → LangBot / SqlBot 的跳转链路；
3. 后续更新
4. 部署；
5. 回滚镜像与数据；
6. 日常运维与排障。

部署文件全部在 [`deploy/prod/`](../deploy/prod/) 和 [`deploy/portal/`](../deploy/portal/) 下，本文与这两个目录配套使用。

### 0.1 部署拓扑

```text
浏览器 http://192.168.31.66:5300
        |
        v
portal_gateway (nginx:1.27-alpine)  ← 唯一暴露到宿主机的服务
        |
        |-- 其他路径 ------------------> langbot:5300
        |                                 （宿主机只绑定 127.0.0.1:5301）
        |
        `-- /sqlbot/* -----------------> sqlbot:8000
                                          （CONTEXT_PATH=/sqlbot，不映射宿主机端口）
```

- `portal_gateway` 占 5300，负责统一入口、路径分流、WebSocket/SSE 透传和上传大小限制。
- 应用中心是 LangBot 内置的 `/portal` 页面，不是独立服务；它随 `langbot` 镜像一起部署。
- LangBot 只在回环地址 `127.0.0.1:5301` 暴露，浏览器不能直接访问 5301。
- SqlBot 不发布宿主机端口，只能经网关 `/sqlbot/` 或 Compose 内网访问。
- 网关把内部开票接口 `/sqlbot/api/v1/system/langbot/sso/ticket` 直接返回 404；LangBot 通过 Compose 网络直连 `http://sqlbot:8000` 调用它。

### 0.2 服务与端口

| 服务                       | 容器内端口         | 宿主机端口         | 说明                                |
| -------------------------- | ------------------ | ------------------ | ----------------------------------- |
| `portal_gateway`         | 80                 | `5300`           | 浏览器唯一入口                      |
| `langbot`                | 5300               | `127.0.0.1:5301` | WebUI、登录、应用中心、API、Webhook |
| `langbot_plugin_runtime` | 5400 / 5401        | `127.0.0.1:5401` | 插件运行时；5401 仅本机调试         |
| `langbot` 平台反连       | 2280–2285         | `2280-2285`      | 需要反连的平台适配器使用            |
| `sqlbot`                 | 8000 / 8001 / 5432 | 不发布             | API、MCP、内嵌 PostgreSQL           |

### 0.3 登录与应用中心链路

需求对应的实际行为：

```text
1. 浏览器打开 http://192.168.31.66:5300
2. nginx 把请求转给 LangBot；未登录时前端进入 /login
3. 账号密码或 CAS 登录成功，LangBot 签发 JWT
4. system.portal.enabled=true 时，登录成功跳转 /portal 应用中心
5. 应用中心两张卡片：
   - LangBot -> /home/monitoring
   - SqlBot  -> 调 POST /api/v1/user/sqlbot/sso-ticket
                LangBot 生成一次性 ticket，并把绑定密钥写入
                HttpOnly cookie（path=/sqlbot/）
                浏览器跳转 /sqlbot/#/login?sso_ticket=...
                SQLBot 兑换 ticket，建立自己的会话，进入 SqlBot 首页
```

**“nginx 拦截”的边界**：nginx 是网络层的统一入口，所有浏览器请求必须先经过它；但 nginx 本身不校验账号密码，身份认证仍由 LangBot 的登录页和 JWT 完成。直接访问 `http://192.168.31.66:5300/sqlbot/` 仍会看到 SqlBot 自己的登录页，这是当前实现的已知边界。如果要求“除应用中心 ticket 外禁止直接进入 SqlBot”，需要额外在 nginx 上实现网关级鉴权（本期未实现）。

### 0.4 为什么必须本机构建镜像

服务器无法访问 Docker Hub、阿里云镜像仓库、PyPI、npm，`docker pull` 和镜像构建都会失败。因此：

- **本机**（有外网）负责构建 LangBot、SqlBot、nginx 网关三个镜像；
- 服务器只执行 `zstd -dc | sudo docker load`，不执行任何 `docker build` 或 `docker pull`；
- Compose 中所有服务都设置了 `pull_policy: never`。

### 0.5 本机已核实的事实（2026-10-28）

- 服务器 `5300` 空闲；`80`、`443`、`3000` 已被现有 `lingnan-production` 栈占用，本方案不使用这些端口。
- `/opt/langbot` 尚不存在，首次部署需要创建。
- 服务器有 `zstd`、`rsync`，**没有宿主机 nginx**（本方案的 nginx 是容器），没有 `sqlite3`，未启用 `ufw`。
- 服务器可用磁盘约 836 GB，内存 15 GB。
- 本机是 x86_64 Mac，Docker 原生 `amd64`，构建 `linux/amd64` 镜像不需要跨架构模拟。

## 3. 首次部署

### 3.1 本机确认两个仓库的源码

LangBot：

```bash
cd /Users/shenni/repository1/LangBot
git checkout my/custom
git status                 # 必须干净；有改动先提交或 stash
git rev-parse HEAD         # 记下完整 SHA，镜像里会写入此值
```

SQLBot：

```bash
cd /Users/shenni/repository1/SQLBot
git branch --show-current  # 应为 dev
git status                 # 必须干净；有改动先提交或 stash
git rev-parse HEAD         # 记下完整 SHA，用于 SQLBOT_IMAGE 标签
```

> SQLBot 镜像会把整个工作区（含未提交改动）打进镜像。发布前必须确认工作区改动是否要上线，否则镜像标签无法对应到可追溯的提交。
>
> `.dockerignore` 已排除 LangBot 的 `data/`、`deploy/`、`.env` 等本地内容，避免把本机数据库和密钥打进镜像。

### 3.2 构建三个镜像（本机）

一条命令构建 LangBot、nginx 网关，并在设置 `SQLBOT_SOURCE_DIR` 时额外构建 SqlBot：

```bash
cd /Users/shenni/repository1/LangBot

SQLBOT_SOURCE_DIR=/Users/shenni/repository1/SQLBot \
SQLBOT_IMAGE=sqlbot:1.10.3-<SQLBot的12位SHA> \
./deploy/prod/build-image.sh
```

示例（提交会变化，以实际 `git rev-parse` 为准）：

```bash
SQLBOT_SOURCE_DIR=/Users/shenni/repository1/SQLBot \
SQLBOT_IMAGE=sqlbot:1.10.3-7b81d62ff51f \
./deploy/prod/build-image.sh
```

脚本行为：

- 读取 `pyproject.toml` 版本号和 LangBot 当前 git SHA，生成唯一标签 `langbot:<version>-<12位SHA>`；
- 以 `linux/amd64` 构建；
- 通过 `LANGBOT_BUILD_REVISION` 把提交号写进 LangBot 镜像；
- 构建完成后运行一次镜像，打印实际写入的提交号用于核对；
- 构建网关镜像 `langbot-portal-gateway:<12位SHA>`；
- 设置 `SQLBOT_SOURCE_DIR` 时，用 SQLBot 仓库的 `Dockerfile` 构建 `SQLBOT_IMAGE`；不设置时跳过，并提示到 SQLBot 仓库单独构建；
- LangBot 和网关标签分别写入 `deploy/prod/.last-image`、`.last-gateway-image`；构建 SqlBot 时另写入 `.last-sqlbot-image`。

构建耗时与体积（首次）：

| 镜像                       | 首次耗时    | 说明                                      |
| -------------------------- | ----------- | ----------------------------------------- |
| `langbot`                | 10–20 分钟 | 约 1.7 GB，含 WebUI 与 Python 依赖        |
| `langbot-portal-gateway` | 秒级        | 基于 `nginx:1.27-alpine`                |
| `sqlbot`                 | 15–40 分钟 | 数 GB，含 PostgreSQL、模型、前端和 g2-ssr |

> 也可以指定 LangBot/网关标签：`./deploy/prod/build-image.sh langbot:4.11.2-20261028`。**标签不可复用**，每次更新都用新标签，旧标签保留在服务器上作为回滚目标。

### 3.3 传输并加载镜像（本机执行）

```bash
./deploy/prod/ship-image.sh
```

脚本会读取存在的 `.last-*-image` 标记并依次传输；也可显式指定：

```bash
./deploy/prod/ship-image.sh \
  langbot:4.11.2-537c0384d977 \
  sqlbot:1.10.3-7b81d62ff51f \
  langbot-portal-gateway:537c0384d977
```

每个镜像的处理流程：

1. 校验镜像是 `linux/amd64`；
2. `docker save | zstd` 压缩到 `deploy/prod/dist/`；
3. 计算 SHA-256，`scp` 到 `192.168.31.66:/opt/langbot/images/`；
4. 在服务器复核校验和；
5. `zstd -dc | sudo docker load`；
6. 打印服务器上的 `langbot:*`、`sqlbot:*`、`langbot-portal-gateway:*` 标签列表。

可用环境变量覆盖目标：

```bash
DEPLOY_HOST=jj@192.168.31.66 DEPLOY_DIR=/opt/langbot ./deploy/prod/ship-image.sh
```

> 服务器不需要、也不要执行 `docker pull`。如果 `ship-image.sh` 在服务器上加载失败，先检查压缩包是否完整（校验和不一致会中止）。

### 3.4 初始化服务器目录

```bash
ssh jj@192.168.31.66

sudo mkdir -p /opt/langbot/{data,sqlbot-data,backups,images,wheelhouse}
sudo chown -R jj:jj /opt/langbot
```

把部署文件复制上去（也可在本机执行）：

```bash
scp deploy/prod/docker-compose.yaml \
    deploy/prod/.env.example \
    deploy/prod/backup.sh \
    jj@192.168.31.66:/opt/langbot/
ssh jj@192.168.31.66 'chmod +x /opt/langbot/backup.sh'
```

创建运行配置：

```bash
ssh jj@192.168.31.66
cd /opt/langbot
cp .env.example .env
chmod 600 .env
vim .env
```

必须修改或确认的项：

| 变量                                     | 说明                                                          |
| ---------------------------------------- | ------------------------------------------------------------- |
| `LANGBOT_IMAGE`                        | 3.2 构建出的 LangBot 标签                                     |
| `SQLBOT_IMAGE`                         | 3.2 构建出的 SqlBot 标签                                      |
| `PORTAL_GATEWAY_IMAGE`                 | 3.2 构建出的 nginx 网关标签                                   |
| `PUBLIC_ORIGIN`                        | 浏览器实际访问源，`http://192.168.31.66:5300`，不带结尾斜杠 |
| `LANGBOT_WEBHOOK_PREFIX`               | 与 `PUBLIC_ORIGIN` 保持一致                                 |
| `SSO_CAS_SERVICE_BASE_URL`             | 如启用 CAS，与 `PUBLIC_ORIGIN` 保持一致                     |
| `PORTAL_ENABLED`                       | 首次启动先设为 `false`，验证通过后改 `true`               |
| `PORTAL_SQLBOT_ENABLED`                | 首次启动先设为 `false`，验证通过后改 `true`               |
| `SQLBOT_SSO_ENABLED`                   | 设为 `true`，否则应用中心的 SqlBot 卡片无法登录             |
| `SQLBOT_SSO_SHARED_SECRET`             | LangBot 与 SqlBot 共用的 HMAC 密钥                            |
| `LANGBOT_PLUGIN_RUNTIME_CONTROL_TOKEN` | 插件运行时控制密钥，两个服务自动共用                          |
| `SQLBOT_SECRET_KEY`                    | SqlBot 应用密钥                                               |
| `SQLBOT_POSTGRES_PASSWORD`             | SqlBot 内嵌 PostgreSQL 密码                                   |
| `SQLBOT_DEFAULT_PWD`                   | SqlBot 导入/创建账号的初始密码                                |
| `LANGBOT_GLOBAL_API_KEY`               | 不用 HTTP API/MCP 就留空                                      |

生成密钥（每条命令生成一个，分别填入对应变量）：

```bash
openssl rand -hex 32
```

至少为以下四项各生成一个不同的值：

- `LANGBOT_PLUGIN_RUNTIME_CONTROL_TOKEN`
- `SQLBOT_SSO_SHARED_SECRET`
- `SQLBOT_SECRET_KEY`
- `SQLBOT_POSTGRES_PASSWORD`

`SQLBOT_SSO_SHARED_SECRET` 在 Compose 中同时注入为 LangBot 的 `SQLBOT__SSO__SHARED_SECRET` 和 SqlBot 的 `LANGBOT_SSO_SHARED_SECRET`，两边必须完全一致。

校验 Compose 配置（不会启动）：

```bash
sudo docker compose --env-file .env config -q && echo OK
```

### 3.5 可选：CAS 统一身份认证

默认 `SSO_CAS_ENABLED=false`。如需启用，按 [`docs/统一身份认证单点登录.md`](统一身份认证单点登录.md) 配置，并在 `.env` 中设置：

```dotenv
SSO_CAS_ENABLED=true
SSO_CAS_BASE_URL=https://sso.example.edu.cn/lyuapServer
SSO_CAS_SERVICE_BASE_URL=http://192.168.31.66:5300
SSO_CAS_STATE_SECRET=<openssl rand -hex 32>
SSO_CAS_ALLOWED_USER_TYPES=teacher
```

回调地址为 `http://192.168.31.66:5300/api/v1/user/sso/cas/callback`，必须与认证平台登记值逐字符一致。使用网关后，这个地址是 **5300**，不是内部的 5301。

### 3.6 离线插件依赖源（涉及插件安装时必做）

插件运行时在安装插件时会执行 `pip install`。服务器不能访问 PyPI，因此需要：

1. 在本机收集插件依赖，生成 wheelhouse 和 PEP 503 索引；
2. 把 wheelhouse 传到服务器；
3. 用 systemd 在 `8081` 端口提供索引服务。

#### 3.6.1 收集依赖（本机）

把要安装的插件的 Python 依赖写进 `deploy/prod/plugin-requirements.txt`，然后：

```bash
./deploy/prod/make-wheelhouse.sh

tar -czf deploy/prod/dist/wheelhouse.tar.gz \
    -C deploy/prod/dist/wheelhouse .
```

脚本会下载 `cp312 / manylinux2014_x86_64` 的二进制 wheel，并生成 `simple/<包名>/index.html`。

> 如果没有纯二进制 wheel（`--only-binary=:all:` 失败），说明该包需要源码编译。需在能上网的相同平台机器上构建 wheel 后放入 `packages/`，不建议在服务器上现场编译。

#### 3.6.2 部署到服务器

```bash
scp deploy/prod/dist/wheelhouse.tar.gz jj@192.168.31.66:/opt/langbot/
scp deploy/prod/langbot-wheelhouse.service jj@192.168.31.66:/tmp/

ssh jj@192.168.31.66
cd /opt/langbot
tar -xzf wheelhouse.tar.gz -C wheelhouse
sudo chmod -R a+rX /opt/langbot/wheelhouse

sudo mv /tmp/langbot-wheelhouse.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now langbot-wheelhouse
curl -fsS http://127.0.0.1:8081/simple/ | head
```

`.env` 中已默认配置：


### 3.9 部署后配置（WebUI）

1. **模型**：在 LangBot WebUI 配置 LLM 服务地址、API Key、模型名。
   - 服务器不能出网。若使用公网模型，必须在内网提供同协议代理，否则调用会超时。
2. **知识库/嵌入模型**：如涉及向量化，同样需要内网可达的 embedding 服务。
3. **平台适配器**：企业微信、QQ、飞书等需要出网；纯内网环境先使用 Web 嵌入或 HTTP API。
4. **插件**：市场已禁用。需要插件时从本地 `.lbpkg` 文件导入，并确保其依赖已进入 wheelhouse。
5. **SqlBot 数据源**：在 SqlBot 中配置内网数据库；不要填写无法从容器内访问的 `localhost`（容器内的 `localhost` 是 SqlBot 自己）。
6. **SqlBot 工作区**：`SQLBOT_SSO_DEFAULT_WORKSPACE_ID` 默认 `1`，首次部署一般无需修改；如果 SqlBot 中实际工作区 ID 不同，需要改成对应值。

### 3.10 内网限制速查

| 能力                        | 纯内网是否可用 | 说明                                      |

### 6.1 常用命令

```bash
cd /opt/langbot
```

### 6.2 配置修改规则

- **WebUI 内修改**：LangBot 的模型、流水线、知识库、平台等，保存在 `data/` 中。
- **SqlBot 内修改**：数据源、问数配置等，保存在 `sqlbot-data/` 中。
- **`.env` 修改**：镜像标签、端口、访问源、密钥、应用中心开关、脱网开关、并发预算。

Compose 中的 `SECTION__SUBSECTION__KEY` 环境变量会在每次启动时**覆盖并写回** `data/config.yaml`。这些键不要直接改 `config.yaml`，否则重启后会被覆盖：

- `API__WEBHOOK_PREFIX`
- `API__GLOBAL_API_KEY`
- `BOX__ENABLED`
- `SPACE__DISABLE_TELEMETRY` / `SPACE__DISABLE_MODELS_SERVICE` / `SPACE__EXECUTION_TRACE`
- `PLUGIN__ENABLE_MARKETPLACE`
- `SYSTEM__PORTAL__*`
- `SQLBOT__*`
- `SSO__CAS__*`
- `SYSTEM__BLOCKING_EXECUTOR__*`

改完 `.env` 后：

```bash
sudo docker compose --env-file .env up -d
```

只改了 LangBot 的变量时，可以只重建 LangBot：

```bash
sudo docker compose --env-file .env up -d langbot
```

## 7. 故障排查

| 现象                                                           | 排查方向                                                                                                                                                                                  |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 浏览器打不开 5300                                              | `sudo docker compose ps` 看 `portal_gateway` 是否运行；`sudo docker compose logs portal_gateway`                                                                                    |
| 网关返回 502                                                   | 后端未就绪或容器名解析失败；看 `langbot`/`sqlbot` 日志和健康状态                                                                                                                      |
| 访问 5301                                                      | 5301 只绑定回环，浏览器必须用 5300 网关地址                                                                                                                                               |
| 登录后仍进 `/home`，没有应用中心                             | `PORTAL_ENABLED=true` 后是否执行了 `up -d langbot`；`/api/v1/system/info` 的 `data.portal.enabled` 是否为 true                                                                    |
| 应用中心只有 LangBot 卡片                                      | `PORTAL_SQLBOT_ENABLED=true`；`SQLBOT_SSO_ENABLED=true`；重建 LangBot                                                                                                                 |
| SqlBot 卡片置灰                                                | 同上；另外检查 `SQLBOT__SSO__SHARED_SECRET` 是否非空                                                                                                                                    |
| 点击 SqlBot 提示暂不可用                                       | LangBot 无法访问 `http://sqlbot:8000`；两个容器是否在同一 `langbot_network`；`sqlbot` 是否 healthy                                                                                  |
| SqlBot 跳转后回到登录页                                        | `SQLBOT_SSO_SHARED_SECRET` 与 SqlBot 的 `LANGBOT_SSO_SHARED_SECRET` 不一致；或 ticket 过期（默认 60 秒）；或 binding cookie 被浏览器拒绝（检查 `PUBLIC_ORIGIN` 与访问地址是否一致） |
| `/sqlbot/` 返回 404 或空白                                   | `SQLBOT_CONTEXT_PATH` 与 SqlBot 的 `CONTEXT_PATH` 必须都是 `/sqlbot`；网关必须保留前缀                                                                                              |
| `/sqlbot/` 静态资源 404                                      | 前端构建时的 base path 与 `/sqlbot` 不一致；确认使用本仓库定制版 SQLBot 镜像                                                                                                            |
| 网关访问 `/sqlbot/api/v1/system/langbot/sso/ticket` 返回 404 | 这是预期行为；该接口只允许 LangBot 走 Compose 内网调用                                                                                                                                    |
| SqlBot 一直 unhealthy                                          | 首次初始化 PostgreSQL 需要 1–3 分钟；超过后看 `sqlbot` 日志和 `sqlbot-data/postgresql` 权限                                                                                          |
| SqlBot 数据重启后丢失                                          | 检查 `SQLBOT_DATA_DIR` 是否指向持久化目录，`docker compose config` 中 volume 是否正确                                                                                                 |
| 上传 Excel 失败 / 413                                          | 网关 `client_max_body_size` 为 200m；超大文件需要同时调整网关和 SqlBot 限制                                                                                                             |
| 插件运行时 unhealthy                                           | 端口 5400 被占用、镜像不完整；查看 `langbot_plugin_runtime` 日志                                                                                                                        |
| 核心连不上插件运行时                                           | 两个服务的 `LANGBOT_PLUGIN_RUNTIME_CONTROL_TOKEN` 必须一致；`ws://langbot_plugin_runtime:5400` 由 Compose 网络解析                                                                    |
| 插件安装失败                                                   | 检查 wheelhouse 服务与 `LANGBOT_PLUGIN_PYPI_*`；容器内 `curl http://192.168.31.66:8081/simple/`                                                                                       |
| 模型调用超时                                                   | 服务器无法访问公网；改为内网地址或代理                                                                                                                                                    |
| WebUI 打开空白                                                 | 确认访问的是 5300 网关，不是 5301；确认镜像内置前端                                                                                                                                       |
| 平台收不到回调                                                 | `LANGBOT_WEBHOOK_PREFIX` 必须是平台可达的地址；纯内网平台无法回调                                                                                                                       |
| 更新后启动报数据库错误                                         | 执行第 5.3 节恢复备份                                                                                                                                                                     |
| 想确认运行的是哪次提交                                         | `sudo docker compose exec langbot /app/.venv/bin/python -c "import langbot._build_info as b; print(b.CORE_REVISION)"`                                                                   |

- 浏览器入口只有 `portal_gateway` 的 `5300`；`2280-2285` 是平台反连端口，按需保留并限制来源，其余端口不要映射到公网。
- `5301`、`5401` 只绑定 `127.0.0.1`，仅供本机调试。
- `sqlbot` 不发布宿主机端口，只能经网关或 Compose 内网访问。
- 网关对浏览器屏蔽 SqlBot 内部开票接口和 API 文档路径；不要删除这些规则。
- `.env` 权限 `600`，不要提交到 git；备份包包含 `.env`，按敏感数据保管。
- `LANGBOT_PLUGIN_RUNTIME_CONTROL_TOKEN` 必须设置，防止内网其他主机连上插件运行时控制端口。
- `SQLBOT_SSO_SHARED_SECRET` 必须设置，且只在 LangBot 与 SqlBot 之间共享；不要写入前端或日志。
- `SQLBOT_POSTGRES_PASSWORD`、`SQLBOT_SECRET_KEY` 使用独立强随机值，不要复用 LangBot 的 JWT 密钥。
- SqlBot 容器按官方要求以 `privileged: true` 运行内嵌 PostgreSQL；它只在内网 Compose 网络中，不直接暴露端口。若安全基线禁止 privileged，需要先与 SqlBot 供应商确认替代方案。
- 直接访问 `/sqlbot/` 会看到 SqlBot 自己的登录页。如果要求“只能从应用中心进入”，需要额外的网关级鉴权；本期未实现，应在上线说明中向使用方明确。
- 对外提供 HTTP API / MCP 时设置 `LANGBOT_GLOBAL_API_KEY`，并定期轮换。
- 镜像标签基于提交号，便于审计每次生产变更对应的源码版本；SQLBot 标签也应使用其自身提交号，不要复用 LangBot 的 SHA。
