# LangBot 生产环境部署指南

适用于本仓库（LangBot 4.11.2 定制分支）在内网服务器上的单机 Docker Compose 部署。

覆盖三件事：

1. 首次部署
2. 后续更新部署
3. 回滚镜像

部署文件全部在 [`deploy/prod/`](../deploy/prod/) 下，本文与该目录配套使用。

---

## 0. 环境与边界

| 项目 | 取值 |
|---|---|
| 生产服务器 | `192.168.31.66`，Ubuntu 22.04.5 x86_64 |
| 登录方式 | `jj@192.168.31.66`，免密 SSH，`jj` 有免密 sudo |
| Docker | 已安装并运行；`jj` **不在 `docker` 组**，所有 docker 命令加 `sudo` |
| 资源 | 4 CPU / 15 GB 内存 / 836 GB 可用磁盘 |
| 外网 | **服务器完全不能访问外网，也不能拉取镜像** |
| 镜像来源 | 本机构建 `linux/amd64` 镜像 → 传送到服务器 → `docker load` |
| 部署形态 | 单机 Compose：核心 `langbot` + 插件运行时 `langbot_plugin_runtime` |
| 数据库/存储 | SQLite + 本地存储 + Chroma，全部位于 `/opt/langbot/data` |
| Box 沙箱 | **不部署**，`BOX__ENABLED=false` |
| 本次范围 | 只部署 LangBot；SQLBot 智能问数后续接入 |

### 为什么必须本机构建镜像

服务器无法访问 Docker Hub / PyPI / npm，`docker pull` 和镜像构建都会失败。因此：

- **本机**（有外网）负责构建；
- 服务器只执行 `zstd -dc | sudo docker load`。

## 2. 部署文件说明

```text
deploy/prod/
├── docker-compose.yaml          # 生产 Compose（核心 + 插件运行时）

└── langbot-wheelhouse.service   # 服务器端离线依赖源 systemd 单元
```

服务器目录约定：

```text
/opt/langbot/
├── docker-compose.yaml
├── .env                  # 含镜像标签/密钥，权限 600
├── data/                 # 持久化数据：config.yaml、SQLite、Chroma、上传文件、日志

├── images/               # 传上来的镜像压缩包（可清理）
└── wheelhouse/           # 可选：离线插件依赖源
```

## 3. 首次部署

### 3.1 本机确认源码状态

```bash
cd /Users/shenni/repository1/LangBot
git checkout my/custom
git status                 # 必须干净；有改动先提交
git rev-parse HEAD         # 记下完整 SHA，镜像里会写入此值
```

> `.dockerignore` 已补充排除 `data/`、`deploy/`、`.env` 等本地内容，避免把本机数据库和密钥打进镜像。该文件是仓库文件，随定制分支一起维护。

### 3.2 构建镜像（本机）

```bash
./deploy/prod/build-image.sh
```

脚本行为：

- 读取 `pyproject.toml` 版本号与当前 git SHA，生成唯一标签：`langbot:<version>-<12位SHA>`；
- 以 `linux/amd64` 构建（服务器是 x86_64）；
- 通过 `LANGBOT_BUILD_REVISION` 把提交号写进镜像；
- 构建完成后运行一次镜像，打印实际写入的提交号用于核对；
- 标签写入 `deploy/prod/.last-image`。

首次构建需要拉取基础镜像并安装依赖，通常 10–20 分钟。构建结果约 1.7 GB。

也可以指定标签：

```bash
./deploy/prod/build-image.sh langbot:4.11.2-20261026
```

**原则：标签不可复用。** 每次更新都用新标签，旧标签保留在服务器上，作为回滚目标。

### 3.3 传输并加载镜像（本机执行）

```bash
./deploy/prod/ship-image.sh
# 或显式指定：./deploy/prod/ship-image.sh langbot:4.11.2-xxxxxxxxxxxx
```

脚本行为：

1. `docker save | zstd` 压缩到 `deploy/prod/dist/`；
2. 计算 SHA-256，`scp` 到 `192.168.31.66:/opt/langbot/images/`；
3. 在服务器复核校验和；
4. `zstd -dc | sudo docker load`；
5. 打印服务器上的 `langbot:*` 标签列表。

可用环境变量覆盖目标：

```bash
DEPLOY_HOST=jj@192.168.31.66 DEPLOY_DIR=/opt/langbot ./deploy/prod/ship-image.sh
```

### 3.4 初始化服务器目录

```bash
ssh jj@192.168.31.66

sudo mkdir -p /opt/langbot/{data,backups,images,wheelhouse}
sudo chown -R jj:jj /opt/langbot
```

把部署文件复制上去（也可在本机执行）：

```bash
scp deploy/prod/docker-compose.yaml \
    deploy/prod/.env.example \
    deploy/prod/backup.sh \
    jj@192.168.31.66:/opt/langbot/
ssh jj@192.168.31.66 'chmod +x /opt/langbot/backup.sh'
```

创建运行配置：

```bash
ssh jj@192.168.31.66
cd /opt/langbot
cp .env.example .env
chmod 600 .env
vim .env
```

必须修改的项：

| 变量 | 说明 |
|---|---|
| `LANGBOT_IMAGE` | 改成 3.2 构建出的标签，例如 `langbot:4.11.2-a1b2c3d4e5f6` |
| `LANGBOT_WEBHOOK_PREFIX` | 默认 `http://192.168.31.66:5300`，确认与访问地址一致 |
| `LANGBOT_PLUGIN_RUNTIME_CONTROL_TOKEN` | 建议生成：`openssl rand -hex 32`；两个服务自动共用 |
| `LANGBOT_GLOBAL_API_KEY` | 不用 HTTP API/MCP 就留空 |

校验 Compose 配置（不会启动）：

```bash
sudo docker compose --env-file .env config -q && echo OK
```

### 3.5 离线插件依赖源（可选，但涉及插件安装时必做）

插件运行时在安装插件时会执行 `pip install`。服务器不能访问 PyPI，因此需要：

1. 在本机收集插件依赖，生成 wheelhouse 和 PEP 503 索引；
2. 把 wheelhouse 传到服务器；
3. 用 systemd 在 `8081` 端口提供索引服务。

#### 3.5.1 收集依赖（本机）

把要安装的插件的 Python 依赖写进 `deploy/prod/plugin-requirements.txt`，然后：

```bash
./deploy/prod/make-wheelhouse.sh

tar -czf deploy/prod/dist/wheelhouse.tar.gz \
    -C deploy/prod/dist/wheelhouse .
```

脚本会下载 `cp312 / manylinux2014_x86_64` 的二进制 wheel，并生成 `simple/<包名>/index.html`。

> 如果没有纯二进制 wheel（`--only-binary=:all:` 失败），说明该包需要源码编译。需在能上网的相同平台机器上构建 wheel 后放入 `packages/`，不建议在服务器上现场编译。

#### 3.5.2 部署到服务器

```bash
scp deploy/prod/dist/wheelhouse.tar.gz jj@192.168.31.66:/opt/langbot/
scp deploy/prod/langbot-wheelhouse.service jj@192.168.31.66:/tmp/

ssh jj@192.168.31.66
cd /opt/langbot
tar -xzf wheelhouse.tar.gz -C wheelhouse
sudo chmod -R a+rX /opt/langbot/wheelhouse

sudo mv /tmp/langbot-wheelhouse.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now langbot-wheelhouse
curl -fsS http://127.0.0.1:8081/simple/ | head
```

`.env` 中已默认配置：

```dotenv
LANGBOT_PLUGIN_PYPI_INDEX_URL=http://192.168.31.66:8081/simple
LANGBOT_PLUGIN_PYPI_TRUSTED_HOST=192.168.31.66
```

确认服务器 `8081` 未被占用：

```bash
ss -lntp | grep -E ':(5300|8081)\b' || true
```

后续新增插件依赖时：更新 `plugin-requirements.txt` → 重新执行 `make-wheelhouse.sh` → 重新传目录 → `sudo systemctl restart langbot-wheelhouse`。

### 3.6 首次启动

```bash
ssh jj@192.168.31.66
cd /opt/langbot

sudo docker compose --env-file .env up -d
sudo docker compose ps
```

首次启动会：

1. 启动插件运行时并等待其健康检查通过；
2. 核心创建 `/app/data` 下的配置、SQLite 并执行 Alembic 迁移；
3. WebUI 随镜像内置，无需额外构建。

查看日志：

```bash
sudo docker compose logs -f --tail=200 langbot_plugin_runtime
sudo docker compose logs -f --tail=200 langbot
```

### 3.7 验证

```bash
# 核心健康检查
curl -fsS http://127.0.0.1:5300/healthz

# 插件运行时健康检查（容器内）
sudo docker compose exec langbot_plugin_runtime \
  python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:5400/healthz', timeout=3).getcode())"

# 容器状态：两个服务都应为 healthy
sudo docker compose ps
```

浏览器访问：

```text
http://192.168.31.66:5300
```

首次访问会进入管理员初始化页面，创建管理员账号后登录。

### 3.8 部署后配置（WebUI）

1. **模型**：在 WebUI 配置 LLM 服务地址、API Key、模型名。
   - 服务器不能出网。若使用公网模型，必须在内网提供同协议代理，否则调用会超时。
2. **知识库/嵌入模型**：如涉及向量化，同样需要内网可达的 embedding 服务。
3. **平台适配器**：企业微信、QQ、飞书等需要出网；纯内网环境先使用 Web 嵌入或 HTTP API。
4. **插件**：市场已禁用。需要插件时从本地 `.lbpkg` 文件导入，并确保其依赖已进入 wheelhouse。

### 3.9 内网限制速查

| 能力 | 纯内网是否可用 | 说明 |
|---|---|---|
| WebUI / Web 聊天页 | ✅ | 浏览器与服务器同内网即可 |
| HTTP API / MCP | ✅ | 建议设置 `LANGBOT_GLOBAL_API_KEY` |
| 内网 LLM / 内网 embedding | ✅ | 需在 WebUI 配置 |
| 公网 LLM / 公网 embedding | ❌ | 需内网代理 |
| 企业微信 / QQ / 飞书 / 钉钉 | ❌ | 适配器需要访问平台服务器 |
| 插件市场 | ❌ | 已在 Compose 中禁用，改用 `.lbpkg` 导入 |
| Space 遥测 / 模型服务 | ❌ | 已禁用 |

## 4. 后续更新部署

### 4.1 本机更新源码并构建

```bash
cd /Users/shenni/repository1/LangBot
git checkout my/custom
git fetch upstream
git rebase upstream/master        # 冲突处理见 docs/源码升级维护指南.md

# 建议至少跑一遍相关测试
uv sync --dev
uv run pytest tests/unit_tests -q

./deploy/prod/build-image.sh
```

记录新标签（例如 `langbot:4.11.2-1a2b3c4d5e6f`）。

### 4.2 传输镜像

```bash
./deploy/prod/ship-image.sh
```

**旧镜像不要删除。** 它是回滚目标。

### 4.3 更新前备份（必须）

```bash
ssh jj@192.168.31.66
cd /opt/langbot

# 记录当前镜像标签，回滚时要用
grep '^LANGBOT_IMAGE=' .env

sudo ./backup.sh
```

备份内容：`data/`（SQLite、Chroma、配置、上传文件）+ `docker-compose.yaml` + `.env`。
备份期间容器会短暂停止，完成后自动恢复。

> LangBot 4.x 的数据库迁移是**单向**的。升级后若新版本执行了迁移，仅回退旧镜像可能因表结构不匹配而失败，必须同时恢复备份。

### 4.4 切换镜像并启动

```bash
cd /opt/langbot

# 备份完成后再改
sudo sed -i 's|^LANGBOT_IMAGE=.*|LANGBOT_IMAGE=langbot:4.11.2-1a2b3c4d5e6f|' .env

sudo docker compose --env-file .env up -d
sudo docker compose ps
```

Compose 会对比镜像标签，自动重建使用旧镜像的容器；不会访问任何镜像仓库。

### 4.5 更新后验证

```bash
curl -fsS http://127.0.0.1:5300/healthz
sudo docker compose ps
sudo docker compose logs --tail=200 langbot
sudo docker compose logs --tail=200 langbot_plugin_runtime
```

再登录 WebUI 抽查：登录、模型调用、知识库检索、聊天页。

### 4.6 清理旧资源（确认稳定后再做）

至少保留**上一个**可用镜像和最近一次备份。

```bash
# 查看镜像
sudo docker image ls langbot

# 删除明确不再需要的旧标签（不要用 docker image prune -a）
sudo docker image rm langbot:4.11.2-旧标签
```

## 5. 回滚镜像

### 5.1 仅回滚镜像（新版本未执行破坏性迁移时）

```bash
ssh jj@192.168.31.66
cd /opt/langbot

# 查看可用标签
sudo docker image ls langbot

# 切回上一个标签
sudo sed -i 's|^LANGBOT_IMAGE=.*|LANGBOT_IMAGE=langbot:4.11.2-旧标签|' .env

sudo docker compose --env-file .env up -d
sudo docker compose ps
curl -fsS http://127.0.0.1:5300/healthz
```

如果容器反复重启，先看日志：

```bash
sudo docker compose logs --tail=200 langbot
```

出现数据库字段/表结构错误时，执行 5.2。

### 5.2 镜像与数据一起回滚

前提：4.3 的备份是在**本次更新之前**做的。

```bash
ssh jj@192.168.31.66
cd /opt/langbot

# 查看备份
ls -lh backups/

# 停掉全部服务
sudo docker compose --env-file .env down

# 保留现场，便于排查
sudo mv data "data.failed-$(date +%Y%m%d-%H%M%S)"

# 恢复 data/、docker-compose.yaml、.env（其中的镜像标签也是更新前的）
sudo tar -xzf backups/langbot-<时间戳>.tar.gz

sudo docker compose --env-file .env up -d
sudo docker compose ps
curl -fsS http://127.0.0.1:5300/healthz
```

恢复后核对 `.env` 中的 `LANGBOT_IMAGE` 确实是旧标签。

### 5.3 回滚检查

- `sudo docker compose ps` 两个服务均为 `healthy`；
- `/healthz` 返回 `code: 0`；
- 能登录 WebUI；
- 抽查历史会话、知识库文档是否还在；
- 插件运行时日志无依赖安装失败。

### 5.4 回滚不了怎么办

保留现场目录 `data.failed-*` 和日志：

```bash
sudo docker compose logs --no-color > /tmp/langbot-rollback-$(date +%s).log
```

不要把 `data.failed-*` 直接删除，里面可能包含最后一次写入的数据。

## 6. 日常运维

### 6.1 常用命令

```bash
cd /opt/langbot

sudo docker compose ps                         # 状态
sudo docker compose logs -f --tail=200 langbot # 核心日志
sudo docker compose logs -f --tail=200 langbot_plugin_runtime
sudo docker compose restart langbot            # 只重启核心
sudo docker compose down                       # 停止并移除容器（不动 data/）
sudo docker compose --env-file .env up -d      # 启动
```

### 6.2 配置修改规则

- **WebUI 内修改**：模型、流水线、知识库、平台等，保存在 `data/` 中。
- **`.env` 修改**：镜像标签、端口、webhook 地址、API Key、脱网开关、并发预算。

Compose 中的 `SECTION__SUBSECTION__KEY` 环境变量会在每次启动时**覆盖并写回** `data/config.yaml`。这些键不要直接改 `config.yaml`，否则重启后会被覆盖：

- `API__WEBHOOK_PREFIX`
- `API__GLOBAL_API_KEY`
- `BOX__ENABLED`
- `SPACE__DISABLE_TELEMETRY` / `SPACE__DISABLE_MODELS_SERVICE` / `SPACE__EXECUTION_TRACE`
- `PLUGIN__ENABLE_MARKETPLACE`
- `SYSTEM__BLOCKING_EXECUTOR__*`

改完 `.env` 后：

```bash
sudo docker compose --env-file .env up -d
```

### 6.3 定时备份

以 root 身份添加 cron：

```bash
sudo crontab -e
```

```cron
# 每天 03:17 备份，脚本内部会短暂停止容器
17 3 * * * cd /opt/langbot && ./backup.sh >> /opt/langbot/backups/backup.log 2>&1
```

`backup.sh` 默认保留 14 天，可用 `KEEP_DAYS` 调整。

### 6.4 磁盘与日志

- 容器日志已限制为每个文件 20 MB、最多 5 个；
- 备份默认保留 14 天；
- `data/storage`、`data/chroma` 会随上传文档增长，定期检查：

```bash
du -sh /opt/langbot/data/*
df -h /opt
```

## 7. 故障排查

| 现象 | 排查方向 |
|---|---|
| `langbot` 一直 `starting` | `sudo docker compose logs langbot`；首次启动迁移较慢，等待 2 分钟 |
| 插件运行时 unhealthy | 端口 5400 被占用、镜像不完整；查看 `langbot_plugin_runtime` 日志 |
| 核心连不上插件运行时 | 两个服务的 `LANGBOT_PLUGIN_RUNTIME_CONTROL_TOKEN` 必须一致；`ws://langbot_plugin_runtime:5400` 由 Compose 网络解析 |
| 插件安装失败 | 检查 wheelhouse 服务与 `LANGBOT_PLUGIN_PYPI_*`；容器内 `curl http://192.168.31.66:8081/simple/` |
| 模型调用超时 | 服务器无法访问公网；改为内网地址或代理 |
| WebUI 打开空白 | 确认访问的是 `5300`（镜像已内置前端），不是 `3000` |
| 平台收不到回调 | `LANGBOT_WEBHOOK_PREFIX` 必须是平台可达的地址；纯内网平台无法回调 |
| 更新后启动报数据库错误 | 执行第 5.2 节恢复备份 |
| 想确认运行的是哪次提交 | `sudo docker compose exec langbot /app/.venv/bin/python -c "import langbot._build_info as b; print(b.CORE_REVISION)"` |

---

## 8. 安全与合规

- `5300` 只在内网开放；不要直接映射到公网。
- `.env` 权限 `600`，不要提交到 git。
- `LANGBOT_PLUGIN_RUNTIME_CONTROL_TOKEN` 建议设置，防止内网其他主机连上插件运行时控制端口。
- `5401` 只绑定 `127.0.0.1`，仅供本机调试。
- 对外提供 HTTP API / MCP 时设置 `LANGBOT_GLOBAL_API_KEY`，并定期轮换。
- 镜像标签基于提交号，便于审计每次生产变更对应的源码版本。
