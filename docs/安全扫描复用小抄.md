# 安全扫描复用小抄

以后想对 LangBot / SQLBot 再做一次安全检测，直接把下面的提示词复制给 AI 即可。按场景选一个版本，替换尖括号里的路径或条目。

> 适用对象：`LangBot` 与 `SQLBot` 两个仓库。
> 前提：只做**本地**扫描，禁止连接生产实例。

---

## 一、完整版（推荐，做一次新的基线扫描）

```text
对以下仓库做一次安全/漏洞扫描，先出报告，我确认后再修：
- <仓库1路径，例如 /Users/shenni/repository1/LangBot>
- <仓库2路径，例如 /Users/shenni/repository1/SQLBot>

范围：
- 只扫本地代码、依赖锁文件、Dockerfile 和 compose/K8s 编排；
- 不扫描、不连接任何生产或内网在线实例（例如 192.168.31.66:5300）；
- 不运行 installer、不启动 privileged 容器做动态验证。

安全红线：
- data/、deploy/local/.env 等真实密钥文件只记录路径、权限和字段名，绝不复制值到报告或对话；
- 报告目录权限 700，落盘前统一脱敏（token、密码、连接串、JWT）；
- 发现疑似密钥泄露时只给指纹或脱敏片段，不贴原文。

深度：
- 自动基线：密钥扫描、依赖漏洞、SAST、容器/IaC 配置检查；
- 人工重点审计：未鉴权接口、鉴权/越权、SSRF、SQL 只读绕过、租户/行权限、文件上传与路径穿越、默认口令与密钥管理、CORS/WebSocket 校验；
- 依赖和镜像扫描失败时如实写“未覆盖”，不要写成“通过”。

交付：
1. 一份可复用扫描套件（脚本 + 配置 + 人工审计清单），放在两个仓库之外；
2. 每个仓库一份报告：执行摘要、发现总表、逐条详情（位置、影响、复现、修复建议、严重级别、可信度）；
3. CI 门禁方案（首版 report-only，建基线后再阻断）。

修复规则（等我确认报告后再执行）：
- 按主题分类提交，提交信息用 <type>(<scope>): <subject>；
- 不 push，除非我明确要求；
- 修完说明改了哪些文件、跑了哪些测试、还有哪些残余风险。
```

- 按主题分类提交，不 push；
- 每个主题提交后说明测试/校验结果和残余风险。

## 四、按需追加的参数

在任一版本后补一句即可：

| 需求               | 追加的话                                               |
| ------------------ | ------------------------------------------------------ |
| 只查某一类问题     | `这次只查未鉴权接口和越权问题，其余跳过。`           |
| 只要报告不要改代码 | `本轮只出报告，不改任何代码。`                       |
| 修复后强制复测     | `修复后用同一套命令复跑，并对比修复前后的发现数量。` |
| 接入 CI            | `把扫描接成 GitHub Actions，首版 report-only。`      |
| 指定严重级别       | `只看 Critical 和 High。`                            |
| 输出英文报告       | `报告用英文写，代码位置和报错原文保持原样。`         |

## 五、上次扫描的已知背景（可一并带上，省得重复排查）

```text
已知背景：
- SQLBot 的 g2-ssr、assistant app_secret、AES-ECB、SQL 只读校验、行权限、默认口令已修；
- LangBot 的 QQ 验签、embed token、CORS、媒体头、文件权限、容器能力已修；
- 残余风险：LangBot 插件运行时因 nsjail 仍需 SYS_ADMIN，Box 的 docker.sock 等同宿主机 root。
```

补充说明：

- **SQLBot 已修**：SQL 只读 AST 校验、数据源 AES-GCM、公开接口隐藏 `app_secret`、日志脱敏、Excel 导入路径约束、表/行权限确定性注入、g2-ssr 鉴权、PBKDF2 与登录限速、默认口令轮换、去 `privileged`。
- **LangBot 已修**：QQ webhook Ed25519 验签、embed HMAC 会话令牌、CORS/WebSocket Origin 校验、媒体响应安全头、`config.yaml` 0600、`data/` 0700、容器能力收紧。
- **仍需注意**：插件运行时为 nsjail 保留 `SYS_ADMIN` 与 unconfined profile；启用 Box 时 `docker.sock` 等价于宿主机 root，只应授予可信插件。

## 六、提交与收尾约定

- 提交信息格式：`<type>(<scope>): <subject>`，例如 `fix(api): ...`、`ci(security): ...`。
- 一个主题一个提交；跨主题文件按 hunk 拆分，避免把无关改动混在一起。
- 未明确要求时**不 push**；需要同步内网时再执行 `git push`。
- 修复完成后汇报：改动文件、执行的测试/校验命令、残余风险。
