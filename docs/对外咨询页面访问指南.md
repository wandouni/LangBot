# 对外咨询页面（校外咨询入口）访问与机器人切换指南

> 适用对象：需要把「广东岭南职业技术学院公共咨询机器人」「广东岭南现代技师学院咨询机器人」发给校外访客的管理员、运维和对接学校官网/招生系统的开发。
>
> 关联代码：`web/public/chat.html`、`web/public/chat-jishi.html`、`web/public/chat-shell.js`、`src/langbot/pkg/api/http/controller/groups/pipelines/embed.py`

## 1. 先搞清楚：页面是「壳」，机器人才是「大脑」

两个对外页面本身**不存对话内容，也不存知识库**。它们只做一件事：读一段页面配置，然后把 LangBot 的聊天挂件（embed widget）铺满整个浏览器窗口。

```
访客打开 /chat-jishi.html?embed=<机器人UUID>
        |
        |  chat-shell.js 读取页面内联 JSON，再用 URL 参数覆盖
        v
加载 /api/v1/embed/<机器人UUID>/widget.js
        |
        v
挂件连接 WebSocket，把消息交给该机器人的 Pipeline
```

所以「换一个机器人」不需要改页面、不需要重新打包，**只要换 URL 里的机器人 UUID**。这正是本方案能扛住「管理员删掉旧机器人、新建一个同功能机器人」的原因：页面不变，链接变。

## 3. 默认机器人（不传参数时）

页面内联配置就是「裸链接」的默认值，位置是各页面文件开头的 `<script type="application/json" id="chat-config">` 块：`web/public/chat.html`、`web/public/chat-jishi.html`、`web/public/default.html`。

| 页面                 | 内联配置位置                 | 默认机器人 UUID                          | 默认标题                           | 默认主色    |
| -------------------- | ---------------------------- | ---------------------------------------- | ---------------------------------- | ----------- |
| `/chat.html`       | 文件开头的 `#chat-config`  | `9da8c6a6-b4cc-4922-b23d-3fa015ed85e4` | 广东岭南职业技术学院公共咨询机器人 | `#72030C` |
| `/chat-jishi.html` | 文件开头的 `#chat-config`  | `b4f94b95-9ef4-43eb-84be-1728e2f32d7c` | 广东岭南现代技师学院咨询机器人     | `#0f6fa8` |
| `/default.html`    | 文件开头的 `#chat-config`  | `9da8c6a6-b4cc-4922-b23d-3fa015ed85e4` | 智能咨询机器人                     | `#2563eb` |

**举个具体例子**：直接把 `http://192.168.31.66:5300/chat-jishi.html` 发出去，访客看到的就是技师学院页面、连的是 `b4f94b95-...` 这个机器人。如果这个机器人被删了，这条裸链接就失效了——但页面本身不用改，换第 4 节的 `?embed=` 链接即可。

`default.html` 是通用页面：Logo 用 LangBot 默认机器人图标（`/api/v1/embed/logo`），主色用挂件默认蓝 `#2563eb`，标题和副标题不带任何学校品牌。后台「嵌入代码 → 公开链接」里的「默认页面」选项打开的就是它，适合不需要学校品牌的通用场景；直接打开时默认连接与 `chat.html` 相同的公共咨询机器人。

> 注意：欢迎语优先取机器人后台的「欢迎语」字段；该字段为空时才使用页面自带的 `subtitle`，再没有才用挂件默认文案。快捷提问 Tab 只来自机器人后台保存的「快捷提问分类」，页面不再提供兜底角色；后台没配分类时，欢迎区不显示任何快捷提问，详见场景 D、E、G。

## 3.1 快捷链接导航（仅 `/chat.html`）

桌面端 `/chat.html` 右上角「留言板」左边多了一个白底红字的「快捷链接导航」按钮。访客鼠标移上去（手机上是点一下），会展开 6 个学校招生常用页面的下拉菜单；点任意一条就在**新标签页**打开目标地址，咨询页本身不跳走。对招生老师来说，它相当于把「VR 看校园、查录取、看招生计划」这些散落在官网各处的入口，集中钉在了咨询窗口旁边。

```
                         ┌──────────────────┐ ┌────────┐
                         │ 快捷链接导航  ▾  │ │ 留言板 │
                         └──────────────────┘ └────────┘
                                  │ 悬停
                         ┌────────────────────────┐
                         │ 广 广州校区VR全景    ↗ │
                         │ 清 清远校区VR全景    ↗ │
                         │ 录 录取查询          ↗ │
                         │ 计 招生计划          ↗ │
                         │ 章 招生简章          ↗ │
                         │ 新 新生指南          ↗ │
                         └────────────────────────┘
```

交互细节：

- 鼠标进入按钮约 0.1 秒后展开，移出后约 0.2 秒收起——留这点宽限是为了让指针跨过按钮和菜单之间的 8px 间隙时菜单不会闪一下；
- 键盘可用：`Enter` / 空格展开，`↓` / `↑` 逐项移动，`Home` / `End` 跳到首尾，`Escape` 收起并把焦点还给按钮；
- 点击页面空白处、切换浏览器窗口宽度、或点「留言板」都会先收起菜单；
- 手机（≤480px）上两个按钮移到输入框下方的底部操作条，文案保持完整；菜单从操作条上方展开，左右各留 12px，不会被窄屏裁掉。触屏点按切换展开/收起，见 3.2 节。
- 桌面端点挂件右下角的气泡关闭聊天；手机上气泡在面板打开时隐藏，用头部的「×」（`aria-label="最小化"`）关闭。关闭后「快捷链接导航」和「留言板」会一起隐藏，避免留下没有聊天框可配对的按钮；再点气泡重新打开聊天，按钮自动恢复。这个联动由 `chat.html` 和 `chat-jishi.html` 监听挂件面板的 `lb-visible` class 实现（`watchWidgetPanel()`），面板状态是唯一依据。

链接数据放在 `web/public/chat.html` 开头 `#chat-config` 的 `links` 数组里，由页面底部脚本 `readQuickLinks()` 读取。要增删或改地址，只改这一段 JSON，不用动 CSS/JS：

```json
"links": [
  { "label": "广州校区VR全景", "url": "https://www.720yun.com/vr/89cjtgkkrw7?s=19327510" },
  { "label": "清远校区VR全景", "url": "https://www.720yun.com/vr/408jtgkkuO1?s=19217486" },
  { "label": "录取查询", "url": "https://lnc.edu.cn/zsw/xszn/lqcxl" },
  { "label": "招生计划", "url": "https://lnc.edu.cn/zsw/zsjh/byaejbejqq" },
  { "label": "招生简章", "url": "https://lnc.edu.cn/zsw/zsjz/2021nzsjz" },
  { "label": "新生指南", "url": "https://lnc.edu.cn/zsw/xszn/jtzn" }
]
```

当前 6 条链接对应地址：

| 菜单文案         | 目标地址                                             | 用途                     |
| ---------------- | ---------------------------------------------------- | ------------------------ |
| 广州校区VR全景   | `https://www.720yun.com/vr/89cjtgkkrw7?s=19327510`   | 720 云全景看广州校区     |
| 清远校区VR全景   | `https://www.720yun.com/vr/408jtgkkuO1?s=19217486`   | 720 云全景看清远校区     |
| 录取查询         | `https://lnc.edu.cn/zsw/xszn/lqcxl`                  | 学校官网录取结果查询     |
| 招生计划         | `https://lnc.edu.cn/zsw/zsjh/byaejbejqq`             | 学校官网分专业招生计划   |
| 招生简章         | `https://lnc.edu.cn/zsw/zsjz/2021nzsjz`              | 学校官网招生简章         |
| 新生指南         | `https://lnc.edu.cn/zsw/xszn/jtzn`                   | 学校官网新生入学指南     |

边界与取舍：

- **只认绝对 `http(s)` 地址**：`javascript:`、`data:`、`ftp:`、相对路径、`//host` 这类写法会被静默跳过，防止把页面配置变成跳转/注入入口；写错的条目只是不显示，不会让整个菜单报错。
- **`links` 为空或全部非法时，整个按钮不出现**，页面行为和没加这个功能前一致。
- **快捷链接不归机器人管**：它和标题、主色、Logo 不同，`?config=` 远程 JSON 和 URL 参数都**不会覆盖** `links`，只认页面文件里这一段。这样即使后台误配了远程配置，招生入口也不会消失或被改到别处。
- **不依赖机器人是否可用**：导航在页面脚本执行后立即渲染；即使 `widget.js` 404、聊天框起不来（见第 7 节），6 个招生链接仍可正常使用；「留言板」才依赖机器人 UUID 加载成功。
- 快捷链接目前**只有 `/chat.html` 有**；`/chat-jishi.html` 只有留言板，`/default.html` 两个都没有，但三页共用同一套移动端面板布局。

> 页面改完要按第 8 节同步静态文件：本地 `pnpm dev` 刷新即可，生产需要 `pnpm build` 并把 `web/dist/` 下对应文件同步进容器，**不需要重启 LangBot**。

## 3.2 手机端布局（三个页面）

在宽度 ≤480px 的手机上，`chat.html`、`chat-jishi.html`、`default.html` 共用一套移动端规则。页面本身只负责把按钮放到正确位置，聊天框内部的尺寸、标题省略、键盘避让都由 `web/public/chat-shell.js` 注入到挂件 Shadow DOM 的样式控制。

- **顶部**：机器人标题只占一行，超出显示省略号，不再被重置/关闭按钮压住；头部按钮放大到 36×36。
- **输入区**：输入框字号 16px（小于 16px 时 iOS 聚焦会自动放大整页），发送按钮 44×44，图片按钮 40×40，方便手指点按。
- **底部操作条**：`chat.html` 的「快捷链接导航 / 留言板」、`chat-jishi.html` 的「留言板」从右上角移到输入框下方，高度 64px 并额外加上 `env(safe-area-inset-bottom)` 的 home 指示条安全区。面板通过 `--lb-tools-reserve` 停在操作条上方，不再留出桌面端那 76px 的悬浮气泡缝。
- **键盘避让**：`chat-shell.js` 的 `installViewportTracking()` 监听 `visualViewport`，把可视高度、顶部偏移、底部偏移写成 `--lb-vv-height / --lb-vv-top / --lb-vv-bottom`。键盘弹出时给 `<html>` 加 `lb-keyboard-open`，操作条自动隐藏、面板底部改为键盘顶部，输入框紧贴键盘；键盘收起后恢复。
- **气泡**：手机上面板打开时隐藏悬浮气泡（`.lb-bubble.lb-open { display: none }`），关闭入口改为头部「×」；面板关闭后气泡重新出现，点它可重开。桌面端行为不变。
- **留言板**：遮罩高度跟随 `--lb-vv-height`，320×568 这类小屏上对话框可内部滚动，键盘弹出也不会把「保存」按钮顶到屏幕外。
- **安全区**：三页的 viewport 都带 `viewport-fit=cover`，刘海和圆角区域靠头部/操作条的内边距兜底。

> 手机布局只影响样式和页面脚本，没有新增配置项。生产更新同样只需重新构建并同步 `web/dist/chat.html`、`chat-jishi.html`、`default.html`、`chat-shell.js`。

## 4. URL 参数速查

`chat.html`、`chat-jishi.html`、`default.html` 三个页面共用同一套参数。`chat-shell.js` 支持四个查询参数，合并顺序是「先内联、再远程、最后 URL 覆盖」：

```
页面内联 JSON  ->  ?config=<远程JSON>  ->  ?embed= / ?title= / ?theme=
```

后面一步覆盖前面一步；`embed`、`title`、`theme` 三个参数互相独立，同时出现时各自覆盖自己对应的字段。

| 参数                   | 作用                       | 取值要求                                             | 例子                                                         |
| ---------------------- | -------------------------- | ---------------------------------------------------- | ------------------------------------------------------------ |
| `embed`              | 指定机器人                 | 小写标准 UUID                                        | `?embed=9da8c6a6-b4cc-4922-b23d-3fa015ed85e4`              |
| `title`              | 顶栏标题、浏览器标签页标题 | 文本，最多 120 字                                    | `?title=2026%E5%B9%B4%E6%8B%9B%E7%94%9F%E5%92%A8%E8%AF%A2` |
| `theme` / `accent` | 主色                       | `#RGB` 或 `#RRGGBB`，URL 里 `#` 要写成 `%23` | `?theme=%230f6fa8`                                         |
| `config`             | 远程 JSON 配置文件         | 可访问的 `http(s)://` 地址                         | `?config=https://example.edu.cn/bot-config.json`           |

几个容易踩的点：

- **UUID 必须是小写标准格式**（`8-4-4-4-12` 位十六进制）。后端 `embed.py:39-40` 的校验只认小写；从控制台复制原值最稳。
- **不要直接写 `?theme=#0f6fa8`**。浏览器会把 `#` 后面的内容当成页面锚点，参数直接丢失；必须写成 `%23`。
- **`?embed=` 只换机器人，不换页面品牌**。标题、副标题、Logo 仍来自页面内联配置；快捷提问分类来自目标机器人自己保存的「快捷提问分类」，目标机器人没配就不显示。要连品牌一起换，用 `?config=`。
- **参数可以叠加**：`?embed=<uuid>&title=招生咨询&theme=%230f6fa8`，URL 参数会覆盖内联值和远程配置。
- **快捷链接导航不吃这套参数**：`links` 只由 `chat.html` 内联配置里的页面脚本读取，`?config=`、`?embed=`、`?title=`、`?theme=` 都不会改它。要换链接只能改页面文件，原因见 3.1 节。

## 5. 七个真实场景

### 场景 A：旧机器人被删，新建了同功能机器人

这是最常见的场景。管理员在后台删除了旧机器人，又新建了一个功能相同的机器人，UUID 从 `old...` 变成了 `new...`。

**做法**：不改任何文件，只把对外分发的链接换成：

```
http://192.168.31.66:5300/chat-jishi.html?embed=<新机器人UUID>
```

**具体例子**（假设新 UUID 为 `a1b2c3d4-e5f6-7890-abcd-ef1234567890`）：

```
http://192.168.31.66:5300/chat-jishi.html?embed=a1b2c3d4-e5f6-7890-abcd-ef1234567890
```

访客打开后，页面标题和角色分类还是技师学院那套，但对话已经转到新机器人。旧链接会失效（挂件 404，页面没有聊天框），需要把学校官网、二维码、公众号菜单里的旧链接一并替换。

### 场景 B：临时换标题或主色，不改页面文件

比如招生季要在标题前加「2026」。

```
http://192.168.31.66:5300/chat.html?title=2026%E5%B9%B4%E6%8B%9B%E7%94%9F%E5%92%A8%E8%AF%A2&theme=%2372030C
```

`2026年招生咨询` 的 UTF-8 编码是 `2026%E5%B9%B4%E6%8B%9B%E7%94%9F%E5%92%A8%E8%AF%A2`；`#72030C` 必须写成 `%2372030C`。标题只影响页面顶栏和浏览器标签页，不会改机器人后台配置。

### 场景 C：一个部署服务多所学校/多套配置

如果不想把品牌写死在页面里，可以把配置放到一个可访问的 JSON 文件，例如 `https://example.edu.cn/configs/jishi-2026.json`：

```json
{
  "title": "广东岭南现代技师学院 2026 招生咨询",
  "subtitle": "你好，请问想了解什么？可咨询招生报名、专业设置、就业实习等公开事项。",
  "accent": "#0f6fa8",
  "logo": "https://example.edu.cn/brand/jishi-logo-symbol.png"
}
```

链接写成：

```
http://192.168.31.66:5300/chat-jishi.html?config=https://example.edu.cn/configs/jishi-2026.json&embed=<机器人UUID>
```

行为说明：

- 远程 JSON 与内联配置是**顶层字段浅合并**：同名顶层字段整段覆盖，不会逐项合并。
- 拉取使用 `credentials: 'omit'`，远程文件必须允许跨域读取（返回 `Access-Control-Allow-Origin`）。
- 远程配置拉取失败不会让页面白屏，`chat-shell.js` 只打一条 `console.warn`，然后继续用内联配置启动。
- 页面配置传给挂件的字段（标题、副标题、主色、Logo）以 `data-*` 形式注入，优先于挂件默认值；快捷提问不再来自页面配置，只来自机器人后台保存的分类。

### 场景 D：快捷提问到底从哪里来

现在只有一个来源（`widget.js:277-281`、`widget.js:1356-1359`）：

```text
机器人保存了「快捷提问分类」
        -> 欢迎区显示这些分类 Tab
机器人没配分类
        -> 不显示任何 Tab 和快捷问题
某个分类的 questions 为空
        -> 这个 Tab 不显示问题，也不借用其他分类
```

页面 JSON 里的 `roles` 和旧的「每行一个快捷提问」字段都不再参与普通访客页面。页面文件即使残留旧数据，挂件也不会读取。

**具体例子**：后台给技师学院机器人配了「考生与家长」「校内教师」两个分类，那么 `/chat-jishi.html` 的欢迎区只出现这两个 Tab。清空后台分类并保存后，两个 Tab 都会消失，而不是恢复成页面里曾经写死的六个角色。

### 场景 E：在后台维护文本分类

不用改页面文件，全程在控制台完成：

1. 打开「机器人」→ 选中目标页面机器人 → 「适配器配置」；
2. 找到「快捷提问分类」。它现在是一个文本框，不再有分类标签、添加按钮和逐条问题输入框；
3. 按下面的格式直接输入，保存即可：

```text
考生与家长
学院招收初中毕业生还是高中毕业生？
报名需要什么条件和材料？

校内教师
在哪里查看学校公开校历？
```

格式规则：

- 每个分类名单独一行，分类名后加不加冒号都可以；
- 分类名下面每行写一个问题；
- 空一行分隔下一个分类；
- 最多 6 个分类，每个分类最多 12 个问题，每题最多 200 字；
- 留空表示不配置后台分类，访客端**不显示任何快捷提问 Tab**。

**具体例子**：上面这段文本保存后，`/chat-jishi.html` 的欢迎区就是「考生与家长」「校内教师」两个 Tab；点「校内教师」只显示校历那一条。不需要重新 `pnpm build`，也不需要同步容器里的 `chat-jishi.html`。

**注意**：清空文本框并保存后，后台分类全部消失，不会恢复页面角色。旧的「快捷提问」字段已不再读取，数据库里遗留的旧值不会影响访客端；页面文件里残留的 `roles` 也不会生效。

### 场景 F：从后台打开公开页面

改完配置并保存后，不必手动拼链接：

1. 打开「机器人」→ 选中目标页面机器人 → 「适配器配置」；
2. 找到「嵌入代码」，点复制按钮右侧的「公开链接」；
3. 在弹出的菜单里选 `chat.html`、`chat-jishi.html` 或 `default.html`；
4. 浏览器新开一个窗口，自动带上 `?embed=<当前机器人UUID>`，地址栏里就是可以直接复制分享的短链接。

**具体例子**：技师学院机器人 `b4f94b95-...`，点「公开链接」→ `chat-jishi.html`，新窗口地址形如：

```
http://192.168.31.66:5300/chat-jishi.html?embed=b4f94b95-9ef4-43eb-84be-1728e2f32d7c
```

几点说明：

- 打开的是**已保存**的配置。改完欢迎语、快捷提问或分类，要先点保存；未保存的草稿不会再通过这个入口预览。
- 刚保存的修改受 `widget.js` 5 分钟缓存影响，可能不会立刻出现在公开页面上。自测想马上确认，可临时在地址后加 `&v=时间戳`，但**分享出去的公开链接不要带 `v`**。
- 按钮只负责打开页面，不会修改或保存机器人配置。
- 如果目标就是页面里写死的默认机器人，分享时可以去掉 `?embed=...`，得到最短链接（如 `http://192.168.31.66:5300/chat-jishi.html`）。
- 历史链接里带的 `#preview=...&previewWelcome=...` 仍能被页面解析打开，但后台界面不再生成这种预览链接。

### 场景 G：欢迎语怎么改

欢迎语有三层来源，优先级从高到低：

```text
机器人后台的「欢迎语」字段（welcome_message）
  -> 独立聊天页自带的 subtitle
    -> 挂件内置的多语言默认文案
```

**做法**：打开「机器人」→ 选中目标页面机器人 → 「适配器配置」→ 找到「欢迎语」文本框，直接修改并保存即可。新机器人的这个字段会预填一段通用欢迎语；已有机器人如果从来没保存过这个字段，仍然显示页面自带的 `subtitle`（技师院、学院页面的品牌文案不会在升级后突然变化）。

> 注意：已有机器人的编辑页也会显示预填的通用欢迎语。如果只改了别的字段顺手保存，这个通用值就会一起落库并覆盖页面 `subtitle`；想保留品牌文案，保存前把「欢迎语」改成页面原来那句，或留空（留空会继续用页面 `subtitle`）。

**具体例子**：把技师学院机器人的欢迎语改成「你好，请问想了解什么？可以咨询招生报名、专业设置、就业实习等公开事项。」并保存，约 5 分钟内（挂件缓存到期）`/chat-jishi.html` 的欢迎区就会换成本句；想立刻确认，可临时在页面地址后加 `&v=时间戳` 绕过缓存，公开链接本身不要带。

几条边界：

- 「欢迎语」**和有没有快捷提问无关**：没有分类 Tab 时欢迎语照常显示；清空分类不会清空欢迎语。
- 把「欢迎语」**保存为空**，会退回到页面 `subtitle`，而不是显示空白。
- `?embed=` 换的是机器人，所以欢迎语会跟着目标机器人的配置走；页面 `subtitle` 只在机器人字段为空时兜底。

## 6. 怎么拿到机器人 UUID

最简单的方式是控制台地址栏：

1. 打开 LangBot 控制台 → 「机器人」；
2. 点开目标机器人，浏览器地址栏会变成类似
   `http://192.168.31.66:5300/home/bots?id=a1b2c3d4-e5f6-7890-abcd-ef1234567890`；
3. `?id=` 后面的值就是机器人 UUID。

注意区分两种 UUID：

| 对象                    | 在哪里找                       | 用途                                                  |
| ----------------------- | ------------------------------ | ----------------------------------------------------- |
| 机器人 UUID（bot_uuid） | 机器人详情页地址栏 `?id=`    | 填 `?embed=`，决定「谁来回答」                      |
| Pipeline UUID           | Pipeline 详情页地址栏 `?id=` | 不要填进 `?embed=`；机器人通过事件绑定指向 Pipeline |

`?embed=` 只接受**机器人 UUID**。填 Pipeline UUID 会得到 404。

## 7. 上线前怎么验证

页面能打开，不代表机器人可用：页面只是静态文件，只要文件存在就返回 200，与机器人状态无关；真正决定聊天能不能起来的是 `widget.js` 接口。

在浏览器或服务器上执行：

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  http://192.168.31.66:5300/api/v1/embed/<机器人UUID>/widget.js
```

| 返回码  | 含义                                                                                                  |
| ------- | ----------------------------------------------------------------------------------------------------- |
| `200` | 机器人可用，页面能正常聊天                                                                            |
| `404` | 机器人不存在、已删除、未启用、不是 `web_page_bot`，或没有绑定 Pipeline 的 `message.received` 事件 |
| `400` | UUID 格式不对（常见原因：带了大写字母、复制不完整、混入了空格或引号）                                 |

> 填成 Pipeline UUID 通常返回 `404` 而不是 `400`：它是合法 UUID，只是找不到对应的 page bot。

然后在浏览器打开最终要分发的链接，确认三件事：

1. 顶栏标题、Logo、主色正确；
2. 欢迎区出现预期的分类标签和问题；后台没配分类时应当完全不出现快捷提问；
3. 随便发一句「你好」，能收到回复；
4. 刷新页面时聊天框应当直接铺满窗口，右下角**不应闪过**一个 400×600 的小弹窗。`chat-shell.js` 会在挂件创建后、浏览器首次绘制前注入全屏样式并关掉入场动画；若仍能看到小窗一闪，通常是浏览器/容器还在用旧版 `chat-shell.js`（见第 8 节同步静态文件）。
5. 点右下角气泡关闭聊天后，桌面端右上角的、手机端底部操作条里的「快捷链接导航」「留言板」应同时消失；再点气泡恢复。
6. 手机（或浏览器开发者工具切到 390×844）上：标题单行省略，两个按钮在输入框下方，聊天框底部没有空白缝；聚焦输入框后操作条隐藏、输入框紧贴键盘。

## 8. 页面改动怎么生效

页面文件在仓库的 `web/public/` 下，Vite 构建时原样复制到 `web/dist/`，由 LangBot 在站点根路径提供。

| 改动位置                    | 生效方式                                                                                                         |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 本地 `pnpm dev`           | 改 `web/public/` 立即生效，刷新即可                                                                            |
| `chat.html` 的快捷链接 `links` | 属于静态文件改动：本地刷新即生效；生产要 `pnpm build` 后同步 `web/dist/chat.html`。后台配置和重启后端都不会改它 |
| 生产容器 `/app/web/dist/` | 重新 `pnpm build`，把 `chat.html`、`chat-jishi.html`、`default.html`、`chat-shell.js`、`brand/` 同步进容器，刷新浏览器 |

本仓库的静态文件统一带 `Cache-Control: no-cache, no-store, must-revalidate`（`src/langbot/pkg/api/http/controller/main.py:255-258`），所以同步完成后**不需要重启 LangBot**，普通刷新就能看到新页面。

但挂件脚本 `widget.js` 是另一条路径，带 `Cache-Control: public, max-age=300`（`embed.py` 的 `serve_widget`）。也就是说，**在后台保存机器人的欢迎语、分类、Logo 等配置后，最多约 5 分钟**外部访客才会看到新内容。后台「公开链接」打开的是保存后的正式页面，不带任何草稿参数，所以看到的效果和访客一致，同样受这段缓存约束；需要立即验证时可在链接后加 `&v=时间戳` 强制拉取新的 `widget.js`。

## 9. 常见故障对照

| 现象                            | 大概率原因                                                       | 处理                                                                           |
| ------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 页面能打开，但没有聊天框        | `widget.js` 404：机器人被删/未启用/不是 page bot/没绑 Pipeline | 用第 7 节的 `curl` 确认，换 `?embed=` 链接                                 |
| 换了 `?embed=` 还是连旧机器人 | 参数被其他查询串截断，或 `&` 写成了 `&amp;`                  | 检查 URL；`#` 必须写 `%23`                                                 |
| 改标题/主色没反应               | 主题色 `#` 没编码；或参数被页面内联值覆盖（优先级写反）        | 用 `?theme=%23RRGGBB`；URL 参数优先级最高                                    |
| 后台欢迎语/分类改了，公开页面还是旧的 | 没保存成功；或 `widget.js` 还在 5 分钟缓存内                  | 确认已保存；等待缓存过期，或重新打开「公开链接」并在 URL 后加 `&v=时间戳`         |
| 后台欢迎语改了，页面显示的还是品牌副标题 | 欢迎语字段保存为空，按优先级退回了页面 `subtitle` | 在「欢迎语」里填写内容并保存，等缓存过期后刷新打开「公开链接」 |
| 后台没配分类，页面却出现旧问题 | 访问的是缓存里的旧 `widget.js`，或浏览器还开着旧页面            | 强制刷新页面；等待 5 分钟缓存过期                                             |
| 页面上看不到「快捷链接导航」 | `#chat-config.links` 为空或全部不是绝对 `http(s)`；或浏览器/容器里还是旧 `chat.html` | 检查 `links` 数组；强制刷新；生产确认已同步新构建的 `dist/chat.html` |
| 手机上底部「快捷链接导航 / 留言板」条消失 | 键盘弹出时操作条会自动隐藏，属正常；键盘收起仍不出现，多半是旧缓存或不支持 `visualViewport` 的旧浏览器 | 先收起键盘；强制刷新；确认已同步新构建的 `dist/chat.html`、`chat-jishi.html`、`chat-shell.js` |
| 手机上聊天框底部有空白缝、悬浮气泡压住输入框 | 浏览器里还是旧 `chat-shell.js`（旧版固定留 76px 给气泡） | 强制刷新；生产确认 `web/dist/chat-shell.js` 已更新 |
| 手机上留言板「保存」被键盘挡住 | 旧页面样式按布局视口定位，没有跟随键盘 | 同步新构建的三页与 `chat-shell.js`；新版遮罩会跟随 `--lb-vv-height` 缩放 |
| 快捷菜单少了一两条           | 该条 `url` 不是绝对 `http(s)` 地址，被页面脚本静默跳过            | 改成完整的 `https://...`，只改 `links` 后重新发布 |
| 远程 `?config=` 不生效        | JSON 语法错误、跨域被拒、字段名拼错                              | 看浏览器控制台 `[chat-shell]` 警告；确认返回 `Access-Control-Allow-Origin` |
| 某个分类没有任何问题按钮        | 该分类 `questions: []`，或文本里分类名下面没有写问题            | 在后台「快捷提问分类」文本框里补齐问题                                         |

## 10. 安全与边界

- 这两个页面是**公开的校外入口**，不要求登录；能不能聊天由机器人 UUID 是否有效、是否启用决定，不依赖用户身份。
- `?embed=` 意味着**知道任意一个有效 page bot UUID 的人都能打开对话**。UUID 本身不可枚举，但如果需要限制滥用，应在机器人后台开启 Turnstile 人机验证，而不是依赖「别人不知道 UUID」。
- 页面隐藏了挂件底部的「Powered by LangBot」（`chat-shell.js` 注入样式里的 `.lb-footer { display: none }`），这是对外品牌要求；嵌入到其他网站的标准挂件不受影响。
- 页面配置里的 `logo`、`?config=` 地址都应由学校自己的 HTTPS 域名提供，避免混合内容被浏览器拦截。

```text
换机器人：  /chat-jishi.html?embed=<机器人UUID>

换整套：    /chat-jishi.html?config=<远程JSON地址>&embed=<机器人UUID>
通用页面：  /default.html?embed=<机器人UUID>
打开公开页：控制台 → 机器人 → 适配器配置 → 嵌入代码 → 公开链接
改欢迎语：  控制台 → 机器人 → 适配器配置 → 欢迎语（留空则用页面 subtitle）
改分类问题：  控制台 → 机器人 → 适配器配置 → 快捷提问分类（文本框，无需改页面）

验证机器人：curl -s -o /dev/null -w '%{http_code}' .../api/v1/embed/<UUID>/widget.js
```

机器人被删除重建时，**只换链接里的 UUID，不动页面文件**。
