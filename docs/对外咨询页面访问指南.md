# 对外咨询页面（校外咨询入口）访问与机器人切换指南

> 适用对象：需要把「广东岭南职业技术学院公共咨询机器人」「广东岭南现代技师学院咨询机器人」发给校外访客的管理员、运维和对接学校官网/招生系统的开发。
>
> 关联代码：`web/public/chat.html`、`web/public/chat-jishi.html`、`web/public/chat-shell.js`、`src/langbot/pkg/api/http/controller/groups/pipelines/embed.py`

## 1. 先搞清楚：页面是「壳」，机器人才是「大脑」

两个对外页面本身**不存对话内容，也不存知识库**。它们只做一件事：读一段页面配置，然后把 LangBot 的聊天挂件（embed widget）铺满整个浏览器窗口。

```
访客打开 /chat-jishi.html?embed=<机器人UUID>
        |
        |  chat-shell.js 读取页面内联 JSON，再用 URL 参数覆盖
        v
加载 /api/v1/embed/<机器人UUID>/widget.js
        |
        v
挂件连接 WebSocket，把消息交给该机器人的 Pipeline
```

所以「换一个机器人」不需要改页面、不需要重新打包，**只要换 URL 里的机器人 UUID**。这正是本方案能扛住「管理员删掉旧机器人、新建一个同功能机器人」的原因：页面不变，链接变。

## 4. URL 参数速查

`chat.html`、`chat-jishi.html`、`default.html` 三个页面共用同一套参数。`chat-shell.js` 支持四个查询参数，合并顺序是「先内联、再远程、最后 URL 覆盖」：

```
页面内联 JSON  ->  ?config=<远程JSON>  ->  ?embed= / ?title= / ?theme=
```

后面一步覆盖前面一步；`embed`、`title`、`theme` 三个参数互相独立，同时出现时各自覆盖自己对应的字段。

| 参数                   | 作用                       | 取值要求                                             | 例子                                                         |
| ---------------------- | -------------------------- | ---------------------------------------------------- | ------------------------------------------------------------ |
| `embed`              | 指定机器人                 | 小写标准 UUID                                        | `?embed=9da8c6a6-b4cc-4922-b23d-3fa015ed85e4`              |
| `title`              | 顶栏标题、浏览器标签页标题 | 文本，最多 120 字                                    | `?title=2026%E5%B9%B4%E6%8B%9B%E7%94%9F%E5%92%A8%E8%AF%A2` |
| `theme` / `accent` | 主色                       | `#RGB` 或 `#RRGGBB`，URL 里 `#` 要写成 `%23` | `?theme=%230f6fa8`                                         |
| `config`             | 远程 JSON 配置文件         | 可访问的 `http(s)://` 地址                         | `?config=https://example.edu.cn/bot-config.json`           |

几个容易踩的点：

- **UUID 必须是小写标准格式**（`8-4-4-4-12` 位十六进制）。后端 `embed.py:39-40` 的校验只认小写；从控制台复制原值最稳。
- **不要直接写 `?theme=#0f6fa8`**。浏览器会把 `#` 后面的内容当成页面锚点，参数直接丢失；必须写成 `%23`。
- **`?embed=` 只换机器人，不换页面品牌**。标题、副标题、Logo 仍来自页面内联配置；快捷提问分类来自目标机器人自己保存的「快捷提问分类」，目标机器人没配就不显示。要连品牌一起换，用 `?config=`。
- **参数可以叠加**：`?embed=<uuid>&title=招生咨询&theme=%230f6fa8`，URL 参数会覆盖内联值和远程配置。

## 5. 七个真实场景

### 场景 A：旧机器人被删，新建了同功能机器人

这是最常见的场景。管理员在后台删除了旧机器人，又新建了一个功能相同的机器人，UUID 从 `old...` 变成了 `new...`。

**做法**：不改任何文件，只把对外分发的链接换成：

```
http://192.168.31.66:5300/chat-jishi.html?embed=<新机器人UUID>
```

**具体例子**（假设新 UUID 为 `a1b2c3d4-e5f6-7890-abcd-ef1234567890`）：

```
http://192.168.31.66:5300/chat-jishi.html?embed=a1b2c3d4-e5f6-7890-abcd-ef1234567890
```

访客打开后，页面标题和角色分类还是技师学院那套，但对话已经转到新机器人。旧链接会失效（挂件 404，页面没有聊天框），需要把学校官网、二维码、公众号菜单里的旧链接一并替换。

### 场景 B：临时换标题或主色，不改页面文件

比如招生季要在标题前加「2026」。

```
http://192.168.31.66:5300/chat.html?title=2026%E5%B9%B4%E6%8B%9B%E7%94%9F%E5%92%A8%E8%AF%A2&theme=%2372030C
```

`2026年招生咨询` 的 UTF-8 编码是 `2026%E5%B9%B4%E6%8B%9B%E7%94%9F%E5%92%A8%E8%AF%A2`；`#72030C` 必须写成 `%2372030C`。标题只影响页面顶栏和浏览器标签页，不会改机器人后台配置。

### 场景 C：一个部署服务多所学校/多套配置

如果不想把品牌写死在页面里，可以把配置放到一个可访问的 JSON 文件，例如 `https://example.edu.cn/configs/jishi-2026.json`：

```json
{
  "title": "广东岭南现代技师学院 2026 招生咨询",
  "subtitle": "你好，请问想了解什么？可咨询招生报名、专业设置、就业实习等公开事项。",
  "accent": "#0f6fa8",
  "logo": "https://example.edu.cn/brand/jishi-logo-symbol.png"
}
```

链接写成：

```
http://192.168.31.66:5300/chat-jishi.html?config=https://example.edu.cn/configs/jishi-2026.json&embed=<机器人UUID>
```

行为说明：

- 远程 JSON 与内联配置是**顶层字段浅合并**：同名顶层字段整段覆盖，不会逐项合并。
- 拉取使用 `credentials: 'omit'`，远程文件必须允许跨域读取（返回 `Access-Control-Allow-Origin`）。
- 远程配置拉取失败不会让页面白屏，`chat-shell.js` 只打一条 `console.warn`，然后继续用内联配置启动。
- 页面配置传给挂件的字段（标题、副标题、主色、Logo）以 `data-*` 形式注入，优先于挂件默认值；快捷提问不再来自页面配置，只来自机器人后台保存的分类。

### 场景 D：快捷提问到底从哪里来

现在只有一个来源（`widget.js:277-281`、`widget.js:1356-1359`）：

```text
机器人保存了「快捷提问分类」
        -> 欢迎区显示这些分类 Tab
机器人没配分类
        -> 不显示任何 Tab 和快捷问题
某个分类的 questions 为空
        -> 这个 Tab 不显示问题，也不借用其他分类
测试页面带 #preview=...
        -> 用后台表单里的当前草稿覆盖已保存分类，即使草稿为空
```

页面 JSON 里的 `roles` 和旧的「每行一个快捷提问」字段都不再参与普通访客页面。页面文件即使残留旧数据，挂件也不会读取。

**具体例子**：后台给技师学院机器人配了「考生与家长」「校内教师」两个分类，那么 `/chat-jishi.html` 的欢迎区只出现这两个 Tab。清空后台分类并保存后，两个 Tab 都会消失，而不是恢复成页面里曾经写死的六个角色。

### 场景 E：在后台维护文本分类

不用改页面文件，全程在控制台完成：

1. 打开「机器人」→ 选中目标页面机器人 → 「适配器配置」；
2. 找到「快捷提问分类」。它现在是一个文本框，不再有分类标签、添加按钮和逐条问题输入框；
3. 按下面的格式直接输入，保存即可：

```text
考生与家长
学院招收初中毕业生还是高中毕业生？
报名需要什么条件和材料？

校内教师
在哪里查看学校公开校历？
```

格式规则：

- 每个分类名单独一行，分类名后加不加冒号都可以；
- 分类名下面每行写一个问题；
- 空一行分隔下一个分类；
- 最多 6 个分类，每个分类最多 12 个问题，每题最多 200 字；
- 留空表示不配置后台分类，访客端**不显示任何快捷提问 Tab**。

**具体例子**：上面这段文本保存后，`/chat-jishi.html` 的欢迎区就是「考生与家长」「校内教师」两个 Tab；点「校内教师」只显示校历那一条。不需要重新 `pnpm build`，也不需要同步容器里的 `chat-jishi.html`。

**注意**：清空文本框并保存后，后台分类全部消失，不会恢复页面角色。旧的「快捷提问」字段已不再读取，数据库里遗留的旧值不会影响访客端；页面文件里残留的 `roles` 也不会生效。

### 场景 F：从后台一键打开测试页

改完标题、快捷提问或分类后，不必手动拼链接：

1. 打开「机器人」→ 选中目标页面机器人 → 「适配器配置」；
2. 找到「嵌入代码」，点复制按钮右侧的「测试页面」；
3. 在弹出的菜单里选 `chat.html`、`chat-jishi.html` 或 `default.html`；
4. 浏览器新开一个窗口，自动带上 `?embed=<当前机器人UUID>`，并把后台表单里**尚未保存**的快捷提问分类放进 URL 锚点 `#preview=...`。

**具体例子**：正在编辑技师学院机器人 `b4f94b95-...`，在「快捷提问分类」文本框里临时输入了两个分类但还没点保存，点「测试页面」→ `default.html`，新窗口地址形如：

```
http://192.168.31.66:5300/default.html?embed=b4f94b95-9ef4-43eb-84be-1728e2f32d7c#preview=%5B%7B%22id%22%3A...
```

这样测的是**当前机器人 + 当前草稿**：快捷提问 Tab 立即显示刚才临时输入的内容，不需要先保存，也不受 5 分钟挂件缓存影响。锚点不会发送给服务器，草稿很长也不会触发请求头超限。按钮只负责打开页面，不会修改或保存机器人配置；标题、Logo 等已有配置仍按第 8 节的缓存规则生效。欢迎语也走同一机制：URL 里会同时带 `previewWelcome=...`，未保存的欢迎语草稿同样立即生效。

### 场景 G：欢迎语怎么改

欢迎语有三层来源，优先级从高到低：

```text
测试页草稿（#previewWelcome=...）
  -> 机器人后台的「欢迎语」字段（welcome_message）
    -> 独立聊天页自带的 subtitle
      -> 挂件内置的多语言默认文案
```

**做法**：打开「机器人」→ 选中目标页面机器人 → 「适配器配置」→ 找到「欢迎语」文本框，直接修改并保存即可。新机器人的这个字段会预填一段通用欢迎语；已有机器人如果从来没保存过这个字段，仍然显示页面自带的 `subtitle`（技师院、学院页面的品牌文案不会在升级后突然变化）。

> 注意：已有机器人的编辑页也会显示预填的通用欢迎语。如果只改了别的字段顺手保存，这个通用值就会一起落库并覆盖页面 `subtitle`；想保留品牌文案，保存前把「欢迎语」改成页面原来那句，或留空（留空会继续用页面 `subtitle`）。

**具体例子**：把技师学院机器人的欢迎语改成「你好，请问想了解什么？可以咨询招生报名、专业设置、就业实习等公开事项。」并保存，约 5 分钟内（挂件缓存到期）`/chat-jishi.html` 的欢迎区就会换成本句；想立刻确认，用「测试页面」打开，草稿不受缓存影响。

几条边界：

- 「欢迎语」**和有没有快捷提问无关**：没有分类 Tab 时欢迎语照常显示；清空分类不会清空欢迎语。
- 把「欢迎语」**保存为空**，会退回到页面 `subtitle`，而不是显示空白；想测试“完全没有欢迎语”的效果，用测试页把草稿清空即可。
- `?embed=` 换的是机器人，所以欢迎语会跟着目标机器人的配置走；页面 `subtitle` 只在机器人字段为空时兜底。

## 6. 怎么拿到机器人 UUID

最简单的方式是控制台地址栏：

1. 打开 LangBot 控制台 → 「机器人」；
2. 点开目标机器人，浏览器地址栏会变成类似
   `http://192.168.31.66:5300/home/bots?id=a1b2c3d4-e5f6-7890-abcd-ef1234567890`；
3. `?id=` 后面的值就是机器人 UUID。

注意区分两种 UUID：

| 对象                    | 在哪里找                       | 用途                                                  |
| ----------------------- | ------------------------------ | ----------------------------------------------------- |
| 机器人 UUID（bot_uuid） | 机器人详情页地址栏 `?id=`    | 填 `?embed=`，决定「谁来回答」                      |
| Pipeline UUID           | Pipeline 详情页地址栏 `?id=` | 不要填进 `?embed=`；机器人通过事件绑定指向 Pipeline |

`?embed=` 只接受**机器人 UUID**。填 Pipeline UUID 会得到 404。

## 7. 上线前怎么验证

页面能打开，不代表机器人可用：页面只是静态文件，只要文件存在就返回 200，与机器人状态无关；真正决定聊天能不能起来的是 `widget.js` 接口。

在浏览器或服务器上执行：

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  http://192.168.31.66:5300/api/v1/embed/<机器人UUID>/widget.js
```

| 返回码  | 含义                                                                                                  |
| ------- | ----------------------------------------------------------------------------------------------------- |
| `200` | 机器人可用，页面能正常聊天                                                                            |
| `404` | 机器人不存在、已删除、未启用、不是 `web_page_bot`，或没有绑定 Pipeline 的 `message.received` 事件 |
| `400` | UUID 格式不对（常见原因：带了大写字母、复制不完整、混入了空格或引号）                                 |

> 填成 Pipeline UUID 通常返回 `404` 而不是 `400`：它是合法 UUID，只是找不到对应的 page bot。

然后在浏览器打开最终要分发的链接，确认三件事：

1. 顶栏标题、Logo、主色正确；
2. 欢迎区出现预期的分类标签和问题；后台没配分类时应当完全不出现快捷提问；
3. 随便发一句「你好」，能收到回复。

## 8. 页面改动怎么生效

页面文件在仓库的 `web/public/` 下，Vite 构建时原样复制到 `web/dist/`，由 LangBot 在站点根路径提供。

| 改动位置                    | 生效方式                                                                                                         |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 本地 `pnpm dev`           | 改 `web/public/` 立即生效，刷新即可                                                                            |
| 生产容器 `/app/web/dist/` | 重新 `pnpm build`，把 `chat.html`、`chat-jishi.html`、`default.html`、`chat-shell.js`、`brand/` 同步进容器，刷新浏览器 |

本仓库的静态文件统一带 `Cache-Control: no-cache, no-store, must-revalidate`（`src/langbot/pkg/api/http/controller/main.py:255-258`），所以同步完成后**不需要重启 LangBot**，普通刷新就能看到新页面。

但挂件脚本 `widget.js` 是另一条路径，带 `Cache-Control: public, max-age=300`（`embed.py` 的 `serve_widget`）。也就是说，**在后台保存机器人的欢迎语、分类、Logo 等配置后，最多约 5 分钟**外部访客才会看到新内容。后台「测试页面」会把当前草稿写进 URL 锚点 `#preview=...&previewWelcome=...`，由挂件优先使用，因此不受这段缓存影响。

## 9. 常见故障对照

| 现象                            | 大概率原因                                                       | 处理                                                                           |
| ------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 页面能打开，但没有聊天框        | `widget.js` 404：机器人被删/未启用/不是 page bot/没绑 Pipeline | 用第 7 节的 `curl` 确认，换 `?embed=` 链接                                 |
| 换了 `?embed=` 还是连旧机器人 | 参数被其他查询串截断，或 `&` 写成了 `&amp;`                  | 检查 URL；`#` 必须写 `%23`                                                 |
| 改标题/主色没反应               | 主题色 `#` 没编码；或参数被页面内联值覆盖（优先级写反）        | 用 `?theme=%23RRGGBB`；URL 参数优先级最高                                    |
| 后台欢迎语/分类改了，公开页面还是旧的 | 没保存成功；或 `widget.js` 还在 5 分钟缓存内                  | 确认已保存；等待缓存过期或清缓存后刷新；测试页面可直接预览未保存草稿          |
| 后台欢迎语改了，页面显示的还是品牌副标题 | 欢迎语字段保存为空，按优先级退回了页面 `subtitle` | 在「欢迎语」里填写内容并保存；测试页可先用草稿确认效果 |
| 后台没配分类，页面却出现旧问题 | 访问的是缓存里的旧 `widget.js`，或浏览器还开着旧页面            | 强制刷新页面；等待 5 分钟缓存过期                                             |
| 远程 `?config=` 不生效        | JSON 语法错误、跨域被拒、字段名拼错                              | 看浏览器控制台 `[chat-shell]` 警告；确认返回 `Access-Control-Allow-Origin` |
| 某个分类没有任何问题按钮        | 该分类 `questions: []`，或文本里分类名下面没有写问题            | 在后台「快捷提问分类」文本框里补齐问题                                         |

## 10. 安全与边界

- 这两个页面是**公开的校外入口**，不要求登录；能不能聊天由机器人 UUID 是否有效、是否启用决定，不依赖用户身份。
- `?embed=` 意味着**知道任意一个有效 page bot UUID 的人都能打开对话**。UUID 本身不可枚举，但如果需要限制滥用，应在机器人后台开启 Turnstile 人机验证，而不是依赖「别人不知道 UUID」。
- 页面隐藏了挂件底部的「Powered by LangBot」（`chat-shell.js:104-107`），这是对外品牌要求；嵌入到其他网站的标准挂件不受影响。
- 页面配置里的 `logo`、`?config=` 地址都应由学校自己的 HTTPS 域名提供，避免混合内容被浏览器拦截。

## 11. 一页速记

```text
默认链接：  /chat-jishi.html
换机器人：  /chat-jishi.html?embed=<机器人UUID>
换标题：    /chat-jishi.html?title=<URL编码后的标题>
换主色：    /chat-jishi.html?theme=%23RRGGBB
换整套：    /chat-jishi.html?config=<远程JSON地址>&embed=<机器人UUID>
通用测试页：/default.html?embed=<机器人UUID>
快速测试：  控制台 → 机器人 → 适配器配置 → 嵌入代码 → 测试页面
改欢迎语：  控制台 → 机器人 → 适配器配置 → 欢迎语（留空则用页面 subtitle）
改分类问题：  控制台 → 机器人 → 适配器配置 → 快捷提问分类（文本框，无需改页面）
验证机器人：curl -s -o /dev/null -w '%{http_code}' .../api/v1/embed/<UUID>/widget.js
```

机器人被删除重建时，**只换链接里的 UUID，不动页面文件**。
