# LangBot 登录页条款文档说明与自托管安全评估

> 评估对象：`http://10.8.16.56:5300/login`
> 评估日期：2026-10-28

## 先说结论

那三份文档是 **LangBot 官方云服务（LangBot Cloud / Space）** 的法律文本，主要约束"使用官方托管服务"的场景。**你自部署在学校内网，法律上的数据处理者是学校自己，不是北京浪波智能科技**——这一点官方隐私政策里写得很明确。

但真正跟你有关的是第三份「数据收集政策」：**自部署实例默认会把运行元数据发到官方服务器**，而你仓库里的配置显示这个开关是开着的。这是最需要处理的一条。

---

## 一、三份文档各是什么

| 文档                                                               | 更新日期           | 核心内容                                                                                                                                                       |
| ------------------------------------------------------------------ | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **服务条款** `/terms`                                      | 2026-08-03         | 针对 **LangBot Cloud 托管服务**。"按现状提供"、不做可用性保证、责任上限为已付费用或 **15 美元**、第三方（LLM/IM 平台）不负责、可随时修改或终止服务 |
| **隐私政策** `/privacy`                                    | v1.5，2026-09-15   | 官方收集哪些账号/支付/使用数据、存储位置（**日本东京 Vultr**，CDN Cloudflare）、保留期限、PIPL/GDPR 权利、跨境传输                                       |
| **数据收集政策** `/docs/zh/insight/data-collection-policy` | 对应 4.11 schema 2 | **专门讲自部署实例的遥测**：默认开启、发到哪里、发什么字段、怎么关                                                                                       |

关键点在于隐私政策里这句话（第 2.2 / 3.3 / 15 节）：

> 对于自部署的 LangBot Core 实例，**数据控制者是实例运营方，不是北京浪波智能科技**。
> 我们只负责按第 4.2 节所述接收的遥测和诊断数据。

也就是说：学生聊天记录、账号、知识库是**你的责任**；官方只接收遥测。

## 二、你实例的实际状态（实测）

我查了源码，也请求了目标实例的公开接口：

```
GET http://10.8.16.56:5300/api/v1/user/account-info
→ initialized: true
  password_login_enabled: true
  cas_login_enabled: true          ← 接了学校的 CAS 单点登录
  space_login_enabled: false       ← 没有绑定 LangBot 官方账号
```

由此：

- **那行"继续即表示您同意我们的…"对你其实没有约束力**。它是上游代码里**无条件渲染**的（`web/src/app/login/page.tsx:689`），不管你的实例用不用官方云都会显示。这是上游对自托管场景考虑不周的地方。
- 你实例上不会出现"使用 LangBot 账号登录"按钮，因为能力接口查询发现没有 Space 账号（`src/langbot/pkg/api/http/service/user.py:293`）。
- 所以建议把登录页这一行换成**学校自己的使用条款/隐私声明**，避免误导用户以为数据会流向浪波公司。

## 三、真正的问题：默认遥测是开着的

你仓库里的 `data/config.yaml`（已被 `.gitignore` 忽略）当前是：

```yaml
space:
    disable_telemetry: false          # 遥测开启
    execution_trace: all              # 每一次执行都上报
    url: https://space.langbot.app    # 发往官方服务器
```

请在实际服务器（10.8.16.56）上确认同一段。代码里的默认值也一样（`src/langbot/templates/config.yaml:579`）。

### 默认会外发的内容

根据代码（`src/langbot/pkg/telemetry/`）和政策文档：

| 类别         | 具体字段                                                                                                       |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| 标识         | `instance_id`（随机 UUID，**不是硬件指纹**）、`workspace_uuid`、`event_id`、版本、部署类型、时间戳 |
| 执行节点     | 平台事件、路由、Pipeline、Runner、平台 API、工具调用的**操作标识**、结果、起止时间、父子顺序、路由目标   |
| 链路结束     | 整体结果、耗时、节点数、来源、**模型名称**、适配器名、Pipeline 插件名                                    |
| 绑定资源     | 插件、**MCP 服务器名**、知识库、工具、**Skill 名**、模型、平台 API 的标识/名称                     |
| 心跳（每日） | 数据库/向量库类型、沙箱配置与可用性、适配器类型、各类资源数量                                                  |
| 错误         | 截断的异常文本（**可能含异常类型和消息前缀**）                                                           |

**明确不采集**：消息正文、提示词、模型回复、平台用户/群 ID、工具参数与结果、凭据、完整堆栈。

发送方式：`POST https://space.langbot.app/api/v1/telemetry`，默认 180 秒一批，失败重试，**无需登录**。留存：明细 30 天、聚合 90 天（政策原文）。

### 还有一条不经这个开关的外连

每次启动都会请求官方版本接口：

```python
# src/langbot/pkg/utils/version.py:32
requests.get('https://space.langbot.app/api/v1/dist/info/releases')
```

它由启动提示 `n001_classic_msgs.py` 触发，**不受 `disable_telemetry` 控制**，也没有配置开关。只关遥测的话，仍然会有这一次出网请求。

## 四、风险评估（按重要性排序）

**🔴 高：数据出境与合规**

即使不含聊天正文，"内网部署的模型名、插件名、MCP 名、知识库、错误前缀、数据库类型"拼起来足以暴露学校内网架构；而且数据落在**日本东京**。对教育行业、等保、个人信息保护要求来说，这通常是不能接受的。**建议关闭 + 防火墙阻断。**

**🔴 高：学生对话会发给第三方 LLM**

这是比遥测更实际的隐私风险。学生与 Bot 的对话内容会完整发送给你配置的模型供应商（DeepSeek/OpenAI/通义等）。需要：

- 明确告知学生/教师；
- 优先用学校私有化或国内合规模型；
- 敏感场景不要接入真实姓名、学号等。

**🟠 中：明文 HTTP**

`10.8.16.56:5300` 是纯 HTTP，登录密码和 JWT Cookie 在校园网内可被嗅探。建议前置 Nginx/Caddy 做 HTTPS，并限制来源网段。

**🟠 中：监听与密钥**

`api.host: 0.0.0.0`；`api.global_api_key` 为空（空则禁用，安全）。**千万不要**为了方便把 `global_api_key` 设成弱口令——它会绕过登录直接访问服务 API 和 MCP。
JWT secret 为空时启动会随机生成（`src/langbot/pkg/core/stages/genkeys.py:24`），这点是安全的。

**🟠 中：插件 / MCP 供应链**

插件从官方市场下载后在插件运行时中执行，MCP Server 可执行任意代码，Box 沙箱也依赖 Docker。内网环境建议：固定版本、审计来源、建立离线白名单，不要让学生随意安装市场插件。

**🟡 低-中：配置细节**

- `sso.cas.insecure_skip_verify` 绝对不能开；
- `service_base_url` 当前是 `http://10.8.16.56:3000`（开发端口），生产要改成正式 WebUI 地址；
- `enabled: 'true'` 写成了字符串，YAML 里应使用布尔 `true`；
- 内部端口（插件运行时 5400/5401、Box 5410、SqlBot 8001、Chroma/Qdrant）不要暴露到校园网。

**🟡 低：上游更新与许可证**

项目是 **Apache 2.0**，允许二次开发和闭源分发，但需保留版权声明。二次开发后要自己跟踪上游安全修复；注意 4.x 不支持从 3.x 数据库升级。

## 五、建议动作

**1）关闭遥测**（`data/config.yaml`，改完重启）：

```yaml
space:
    disable_telemetry: true
```

同时确认没有环境变量覆盖它（环境变量优先级更高，容器还要求重建才生效）：

```bash
grep -R "SPACE__DISABLE_TELEMETRY" deploy/ .env* 2>/dev/null
```

**2）在网络层兜底**（推荐，最彻底）

在服务器出站防火墙/网关阻断这些域名，遥测和版本检查就都出不去了：

```
space.langbot.app
api.langbot.cloud
```

如果将来要用官方模型网关或插件市场，再按需放行。

**3）改掉登录页的条款提示**

把 `web/src/app/login/page.tsx:689` 那段换成学校自己的《使用条款》《隐私说明》，链接指向校内页面。需要重新 `pnpm build` 并替换 `web/dist` 才生效。

**4）生产加固**

- 反向代理 + HTTPS，限制访问网段
- 定期备份 `data/langbot.db`，控制日志权限与轮转
- 插件/MCP 固定版本并审计
- 明确告知师生"哪些数据会发给模型供应商"

---

**一句话总结**：那三份文档本身不是陷阱，是官方云的常规条款；你的自托管实例并不真正受它们约束。真正的风险是**默认开启的遥测会把内网运行元数据发往境外服务器**，以及**学生对话会发给第三方模型**。把 `disable_telemetry` 关掉、出口防火墙阻断官方域名，这两条做完，风险就降下来了。
